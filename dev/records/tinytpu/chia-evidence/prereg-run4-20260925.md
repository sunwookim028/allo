- **Zero candidates graded**, with the stage named. A result about the repair.
- **A win `accept.py` refuses** on a clean worktree with its own bindings: the
  search is producing plausible-but-wrong candidates. A result about the gate
  ladder.
- **The cross-check firing.** A stop, not a datum.
- **A `tamper` verdict on a tree that should have been clean** is, in practice,

- **`smoke.py` failing.** Then the paid path is *not* proven and the run stops

## What would count as a novel design point

Decided by the owner on 2026-09-25, *before* this run, and recorded here
because the series' deliverable is stated as "1-3 novel design points" and that
phrase was undefined until the searchable space was measured.

**A novel design point is a candidate-authored change to the DESIGN -- a unit,
the wiring, or the instruction set -- that beats the run's own measured control
on the objective, and that is not a knob already present in the tree.**

Three things follow, and each is checkable rather than a judgement:

1. **The diff must touch hardware.** An environment variable or a parameter
   flip is not one, however large the win. This excludes run 3's only win by
   construction: `TPU_DMA_WIDEN` already existed in `microarch_isa.py`, off by
   default, and the pre-registration named it as a predicted rediscovery before
   the run.
2. **The rediscovery register must not name it.** Each pre-registration lists
   what a win is expected to re-find; anything on that list is a rediscovery,
   which is worth recording and is not a design point.
3. **The control is the run's own**, measured in the same run, not the
   published row. A change scored against a stale baseline is not a result.

Run 1's front-end win (+27 / -291) would qualify on (1) and (3); whether it
qualifies on (2) is moot, as that run pre-registered nothing. **This run is not
expected to produce one** -- one worker, one iteration, and a question about
the paid path rather than about the design. The definition is recorded now so
that it is not written to fit whatever comes back.

# Result, appended 2026-09-25 after the run

**Primary question: answered, yes.** One graded verdict. `front-end` iteration 1
reached `ACCEPTED` with a nonce-vouched cosim at both scored shapes —
`{'16x16x16': 627, '4x4x4': 175}`, `total_model_cycles` 2397 — against a
control the run measured itself, `{'16x16x16': 674, '4x4x4': 175}`, which
cross-checked against the published row with `agree {0, 0}`. Nothing died at
`setup`, `policy`, `import`, `invariant`, `tamper`, `model`, `gate` or `score`.

**Spend $2.76 of $10**, one session, 56 model messages, wall 57.3 min. Under
the predicted $8, from the database and not from `usage`.

## Two predictions held; one was wrong, and it is the interesting one

- **"Primary: yes, one graded verdict"** — held.
- **"Spend under $8"** — held, $2.76.
- **"No win. I predict `not-better`."** — **falsified.** The candidate was
  accepted, 849 -> 802 total cosim cycles.

The falsification clause was *"an `accept.py`-confirmed win that is not on the
register below"*. **This win IS on the register.** The whole diff is:

```diff
-_WIDEN = TpuParams.widest_burst(T, MAXDIM) if os.environ.get("TPU_DMA_WIDEN") == "1" else 1
+_WIDEN = TpuParams.widest_burst(T, MAXDIM)
```

plus the matching `default_expression` in `isa_spec.json` and the regenerated
`isa_encoding.py`. It removes the guard on `TPU_DMA_WIDEN` so the widest burst
becomes the default. The prediction's *reasoning* was right — "the headroom
they found is nominally still there, which is exactly why a win here would most
likely be a rediscovery" — and its *verdict* was wrong. Recorded as wrong.

## Not a novel design point, by the definition recorded before the run

The definition above requires a change to a unit, the wiring or the instruction
set, **not a knob already present in the tree**, and says explicitly that a
parameter flip is not one however large the win. `TPU_DMA_WIDEN` already
existed in `microarch_isa.py`, off by default. So:

**Three of the series' four wins are now the same operand-burst idea.** Run 1
found it (+27/-291 lines, not landable as written), run 3 rediscovered it as a
named prediction, run 4 removed its guard. The definition caught this on its
first use, which is what it was written for.

The useful reading is not that the loop failed. **It is that the burst knob is
the cheapest legal win in the tree, so a hill-climber with an expensive oracle
goes straight to it every time.** That is a fact about the search's economics,
and it is what the next run series has to design against.
