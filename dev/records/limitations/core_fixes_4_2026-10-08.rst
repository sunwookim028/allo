1. D-14, lowering extended (U4 C2)
==================================

**Before.** ``@ Stateful(reset=False)`` was lowered by the SystemC emitter
only in a Wire-only kernel: its stores moved to a clock-edge ``SC_METHOD(wr)``
with no reset action, under a rule that holds only when one iteration is one
clock edge. Any kernel with a Stream, channel or array port was refused ("the
write runs at every clock edge, which matches the kernel's iterations only
when every port is a Wire"), so the DMA's landing payload (P-7) had no csim
or Catapult path in its declared form: ``dma`` ``bits``/``streams`` and
``dma_vmem`` ``d12`` ran only as ``*_reset`` deviations.

**Change** (``mlir/lib/Translation/EmitSystemC.cpp`` ``planUnreset``,
``UnresetPlan::member``; ``allo/backend/catapult.py`` ``unreset_process_in``,
``unreset_directives``; ``allo/backend/hls.py``). A kernel that is not
Wire-only holds its unreset storage as a **plain module member** that the
thread reads and writes as any ``@ Stateful`` member, with no reset-action
write (the reset action prints ``// <sym>: @ Stateful(reset=False), not reset
(D-14)``). D-11's csim state save reloads it with the thread's other members.
The emitter marks each kernel ``// allo unreset process: wr|run``, and
``run.tcl`` scopes ``-RESET_CLEARS_ALL_REGS no`` to that process
(``/<top>/<kernel>/run`` for the member form). Wire-only kernels are
unchanged (``wr``, the rule and its refusals). Still refused, naming the
storage: a ``Wire[T, comb]`` output reading member storage ("a comb output
reads it in a kernel that is not Wire-only"; comb storage is a signal the
thread writes, which Catapult resets, CIN-233).

**Catapult** (one run, ``catapult_c2/``: ``_regfile_stream(16)``,
``synth_top=rf_0``, 3.33 ns, 43 s): no CIN-233 -- the check applies to
signals, not members -- and the member maps to ``ccs_ram_sync_1R1W`` (32 x 16),
whose ``mem`` has no reset in ``concat_rtl.v``. Final schedule ``/rf_0/run``
latency 2. The scoped directive on ``run`` also leaves unreset any thread
register whose reset value the C semantics do not need (U2 A1's hazard, now
confined to the kernel that declares unreset storage).

**Tests** (``tests/dataflow/test_systemc_unreset.py``, 16 pass, csim
included): ``test_unreset_stream_kernel_emit`` (Stream-port and array-port
kernels: plain member, no ``wr``, no reset write, the thread writes it,
``directive set /top/rf_0/run -RESET_CLEARS_ALL_REGS no`` once);
``test_unreset_stream_kernel_comb_refused``; ``test_unreset_stream_kernel_csim``
(two calls with no reset between: the first writes every word, the second
only reads; simulator and csim equal on every iteration of both calls, the
never-written words of call 1 masked, and call 2 returns the last write per
word). ``_regfile_stream`` left ``test_unreset_refusals``; the Wire-only
refusals (read-modify-write, inner loop) stay.

2. D-12 amended: a port's latency in the owner's iterations (U4 T-2, C8)
========================================================================

**Before.** The ``registers`` server (``allo/compose.py`` ``_server``) wrote a
latency-``L`` read as a pipe of ``L`` entries *as data* and put the last
entry after the shift. On the SystemC target's declared links the data pin is
a registered ``Wire``, so the owner saw the read of iteration ``t`` in
iteration ``t + L``; on Stream links (the simulator; csim of the simulator's
region) a token arrives in the iteration it is put, so the owner saw it in
``t + L - 1`` -- the word *after* the edge that ends ``t + L - 1``. Track A's
``fetch_d12`` therefore kept the IRAM's read register in its body
(``rd_reg``), which the Wire form would count twice; track C's
``dma_vmem`` group held every token one iteration (``hold``), a register that
was not hardware. The pipe was also uninitialised on Stream links (the first
deliveries were stack garbage: 32,571 / 32,601 in the pre-fix runs below).

**Change** (``_server(..., links)``). On Stream links each latency-``L >= 1``
port's last pipe stage is put at the **top** of the server's iteration --
before its shift and before it takes any address -- and the pipe starts at 0;
the declared (Wire) form is unchanged (its register is one of the ``L``
stages). Putting first also removes a deadlock the old order had: the server
took every port's address before any put, so one owner reaching its read
port before its write port, with the write port declared first, blocked both
(found writing the test; ``scripts/pre_fix_t2.py`` declares the read port
first to get past it). ``memory.json`` now says "delivered L owner iterations
after the access" for both link kinds. The rule is written in
``docs/source/developer/dataflow_semantics.rst`` ("Memory ports").

**Test** ``tests/dataflow/test_compose_port_latency.py`` (8 pass): one memory
(8 words, unreset), a ``w`` port and an ``r`` port of latency 1 and 2, one
owner with its own counter reading word ``5c & 7`` and writing word ``c & 7``
every iteration and sending ``(c + 1, data)`` to a sink on ONE link kind, so
the pair cannot be mispaired by the sink's skew. Simulator, csim on Stream
links and csim on Wire links: every defined pair equals the read of iteration
``c - L`` as of before its write, at L = 1 and 2; the manifest text is
checked for both link kinds. The sink reads both links before its (blocking,
in csim) output pushes: written the other way the Wire csim read the tag and
the data a cycle apart and looked one iteration early -- a test artefact,
noted because it is the easy way to write such a sink. Before the fix
(``logs/t2_pre_fix.log``): **41/41 and 40/40 pairs differ, all agreeing at
tag offset -1** (delivered at ``t + L - 1``).

**Units changed with the rule** (the compensation goes, the verdicts hold):

* ``examples/minitpu/units/fetch_d12.py``: ``rd_reg`` removed; ``fq`` reads
  ``mem[next_addr]`` and gets port B's read register. Negative control
  (``logs/t2_fetch_d12_old_body_new_rule.log``): the old body under the new
  rule is ``UNIT-DIFF 23,014/25,026`` -- the register counted twice.
* ``examples/minitpu/units/dma_unit.py`` ``vmem_group``: ``hold`` removed;

* ``examples/minitpu/units/dma_selftimed.py`` ``st_vowner`` (self-timed

3. D-25: flushable streams (U4 T-4/H6, T-5)
===========================================

**Spelling.** Python has no keyword subscripts, so the decision's
``Stream[T, D, flush=True]`` is ``Stream[T, D, flush]``, ``flush`` a marker in
``allo.ir.types`` (as ``comb`` marks a ``Wire``); ``Stream[T, D, flush]`` also
evaluates as a value (``.flush_ok``), and ``compose.Channel(..., flush=True)``
emits it. ``s.flush()`` is the operation.

**What changed.**

* Front end: ``allo/ir/types.py`` (marker, ``Stream.flush_ok``, ``.flush()``),
  ``infer.py`` (the 3-item annotation; ``s.flush()`` refused on a stream not
  declared flushable, naming it), ``builder.py`` (``flush`` attribute on the
  construct; ``s.flush()`` -> ``allo.stream_flush``), ``allo/netlist.py``
  (``flush`` is a read), ``allo/dataflow.py`` (lifted as the consumer side;
  ``check_flush_consumer`` refuses a flush in a kernel that puts to the stream
  or never gets from it, naming stream and kernel).
* IR: ``allo.stream_flush`` (``AlloOps.td``), visitor dispatch, a refusing
  ``emitStreamFlush`` in the Vitis emitter (inherited by Catapult C++).
* Simulator (``allo/backend/simulator.py``): the consumer's head pointer
  jumps to the producer's tail, inside the same OpenMP critical/flush pattern
  as get.
* SystemC (``EmitSystemC.cpp``): ``AlloFifoClr<T, N>``, the fork's cleared
  FIFO -- the vendor ``Connections::Fifo``'s structure (comb ``enq.rdy``,
  ``deq.vld``, ``deq.dat``, next-state methods; one ``Seq`` thread;
  ``FifoElem`` storage) plus a clear. The vendor FIFO has no clear and keeps its
  state ``protected`` in a ``Seq`` thread we cannot extend, so flushable
  streams (only) get the fork's own FIFO. The consumer gets ``sc_out<bool>
  <s>_clr`` driven as a toggle (``<s>_tog`` register, reset to 0): while the
  toggle differs from the FIFO's ``seen`` register the FIFO offers no token,
  and the edge that ends that cycle discards every buffered token and that
  cycle's enqueue -- zero cycles, nothing to deassert, back-to-back flushes are
  back-to-back clears. In csim an ``In`` port under
  ``CONNECTIONS_ACCURATE_SIM`` is itself a one-token buffer; the flush also
  drops that token (``#ifndef __SYNTHESIS__``; found by the first csim run,
  which issued one stale token per flush). Refused by name: depth 0,
  ``empty()``/``full()`` on a flushable stream (no sideband yet). The
  template is appended to the emitted header only when the design flushes a
  stream, so every other design's text is unchanged (a first draft that always
  emitted it moved the TinyTPU SystemC hash to ``c00d88ee…``, +3,408 bytes).
* ``allo/backend/hls.py``: every non-SystemC HLS backend refuses a module with
  ``s.flush()``, naming the channel(s).

**Catapult** (``catapult_d25/``; one run): the test's region with
``AlloFifoClr<ac_int<32,true>,4>`` synthesises (45 s, exit 0); its ``Seq`` is
``Latency = 1`` as the vendor FIFO's; the clear (``clr``/``seen``) is in
``concat_rtl.v``. Warnings: CIN-124 on ``Seq``'s signal writes ("should be
scheduled with iomode=fixed"), which the vendor FIFO does not raise. Not done:
a per-cycle check of the clear on the RTL (Verilator) -- the RTL column is
track D's.

**Tests** ``tests/dataflow/test_stream_flush.py`` (9 pass): a producer one
token per step, a consumer one get every other step and flushes every sixth
step (plus back-to-back flushes in a second trace), per-step ``ack``/``k``
ordering; simulator and csim equal the model on every step, the token after
each flush is the first put after it, the put of the flush step is dropped;
the emitted shape; refusals (producer-side flush, undeclared stream, ``vhls``
and ``catapult`` naming ``s``); the marker. Writing the second trace first
deadlocked the simulator: the producer blocked on a full stream while the
consumer waited for its ``ack`` -- the obligation now written in
``stream_ports.rst`` and asserted by the test's model.

4. S-2: the D-12 server's port order (U4 sequencer loop)
========================================================

Merged ``origin/u1-pilot`` at ``7fba744a`` first (it brings the sequencer-loop
composition, ``examples/minitpu/template/sequencer.py``, and the repro).

**Before** (``dev/records/minitpu/u4_seqloop_2026-10-08.rst``, S-2). The
``registers`` server took each port's address in declaration order with
blocking gets. With the loop buffer declared as the RTL has it (``cap`` write,
then ``replay`` read) the server waited for the capture's address before
answering the replay read that, through loop control and issue, decides that
address: the simulator hung with no message. The composition declared
``replay`` first as a workaround. (For latency ``>= 1`` reads, fix 2 already
put every read before any address; S-2 is the latency-0 case.)

**Change** (``allo/compose.py`` ``_server``): the body serves every port that
reads (``r``, ``rw``) before any write-only port's address get; the writes
still come last, in declaration order, so a read sees the pre-edge word and
Catapult's per-port ``if`` numbering (``_server_ops``) is unchanged.

**Tests.** ``tests/dataflow/test_compose_server_port_order.py`` (2 pass): the
repro's two units, both declaration orders, each build in a child process
with a 120 s timeout (a regression fails instead of hanging the suite); every
read is the previous one + 1. The repro itself now prints ``FIXED`` (both
orders return; ``(w, r)`` used to be killed at 90 s).

**Sequencer** (``logs/s2_sequencer_*.log``): the composition now declares the
ports in the RTL's order (``cap``, ``replay``), and ``SEQ_LB_PORTS=
replay_first`` keeps the workaround's order to compare. The merged
``sequencer.py`` carried its own copy of ``fetch_d12.fq`` with the T-2
read register (``rd_reg``); with fix 2 that register counts twice, so it went
the same way as ``fetch_d12``'s.
