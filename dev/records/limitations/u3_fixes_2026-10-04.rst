The bugs
========

**A3** (core, silent then loud, high). ``decompose_library_function``
(``allo/passes.py``) matched the library ops by prefix: it erased every
module-level symbol whose name starts with ``gelu``, ``layernorm`` or
``tril``, and replaced every call to a function starting with them by the
library body. A constant ``gelu_tab`` vanished (``'memref.get_global' op
'gelu_tab' does not reference a valid global memref``); a user function
``tril_rows`` called at the top of a kernel body was replaced by ``tril``
(``'linalg.yield' op type of yield operand 1 ('f32') doesn't match``). The
sfu unit named its ROMs ``rom_gelu`` to dodge it.

**E1** (front end, silent). A region of plain ``@df.kernel`` functions built
and ran a ``Stream`` no kernel touched, and built a stream only written
(which blocks once full) and emitted SystemC for it. The ``@df.unit``
netlist path refused both (``unconnected-stream``).

**E5** (lowering, loud) and **E4**. ``lower_bit_ops`` ended every
``allo.get_slice`` with ``arith.trunci`` to the result type. The builder
types a slice whose bounds fold only after ``meta_for`` expansion -- and a
full-width one -- with the word's own width, so ``lane: int32 =
w[32*c : 32*(c+1)]`` on a ``UInt(32)`` became ``trunci i32 -> i32`` and the
simulator refused the module. Not a signedness conversion, as E5 was first
read: ``lane: UInt(32)`` fails the same way; ``me_sink``'s unsigned lane
worked because its word was wider. **E4** is this bug: the int8 matrix
engine at DIM=4 slices ``a: int8 = packed[MAC_IN_BITS*r : ...]`` out of a
``UInt(32)`` packed row, typed ``i32`` (the bounds name a global), and
failed at module line 124 with the same message; with the fix it builds and
matches its reference (``run_u3e``: FINDING -> OK). The LLVM backend (no
``meta_for`` simulator pipeline) happened to accept the same IR.

**E3** (HLS emitters, loud). The emitters name each result's output pointer
after the value that defines it, and skip a returned value that is an
argument (an array returned in place). ``def pack_int32(v: int32) -> int32:
return v`` was emitted ``void pack_int32(int32_t v0)`` while every call
passed ``(v, &out)``: g++ "too many arguments" in SystemC csim. Not SystemC
only, as recorded: the Vitis and Catapult emitters print the same signature
(shared ``VhlsModuleEmitter::emitFunctionSignature``).

**A2** (SystemC emitter, loud). A baked-in constant array was declared only
as a ``static const`` local in the thread of each kernel that reads it; a
helper function (a plain C++ function emitted through the base emitter)
reading one referred to an undeclared name (``'rom' was not declared in this
scope``).

**A4** (SystemC emitter, loud). Passing a kernel's constant table to a helper
made the argument ``const int32_t[]`` and the parameter ``int32_t v1[64]``:
``invalid conversion from 'const int32_t*' to 'int32_t*'``. SystemC only:
Vitis declares the global without ``const``.

**A5** (SystemC csim testbench, silent, high). Root cause found: not the
kernel and not the memory model. With stream outputs, the last stream sink
``sc_stop()``\ ped the simulation as soon as it had drained its words, and
memory-port outputs are read after the run; a kernel whose last iteration
pushes its stream words and then stores to a memory lost every store but
the first (the reduction tree's one slot of 204,120; the repro's last row
``[152, 0, 0, 0]``). Stores first, the run outlived them -- which is why the
track's reorder worked.

**E2** (SystemC and Catapult emitters, loud then silent). Isolated: the
``ac_int`` slices were sized by the value's type, not the slice's bounds.
The packing in ``me_feed`` (``packed[MAC_IN_BITS*r : ...] = <i32>`` under
``meta_for``) became ``_bs.set_slc(48, ac_int<32, false>(v))`` on a 64-bit
word: 48 + 32 > 64, ac_int's ``Out of bounds set_slc`` assertion
(``ac_int.h:2912``), and on every lower lane the 16 bits above it
overwritten (harmless only because the lanes are written in ascending
order). Past the abort a second instance of the same defect on the read
side: ``word: UInt(32) = out_word[16*c : 16*(c+1)]`` became ``slc<32>(lo)``,
reading the next lane into the upper half -- bf16 DIM=4 read 7/32 (the
seven whose next lane was zero). The two-engine PE rig (no packed lane
word) never met either. Vitis is unaffected (``v(hi, lo) = x`` truncates).

The fixes
=========

``[Pass] Replace only the builder's library declarations, not user symbols named like them``
   A3. A library op is a bodiless ``func.func`` named ``<op>_<digits>``
   (what ``build_Call`` declares); only calls to those are replaced and only
   those declarations erased.
``[Dataflow] Refuse a stream that a plain kernel region leaves without a writer or a reader``
   E1. ``expand_region_units`` checks a unit-free region too, from every
   nested kernel's stream uses (inside ``meta_if`` or loops as well), and
   raises ``NetlistError`` at the ``@df.region()`` naming the stream: one no
   kernel uses (``no writer and no reader``), or one with a single end that a
   *blocking* ``put``/``get`` uses (``stream 'orphan' has no reader, and k
   blocks on orphan.put() once it is full``). A one-ended stream used only
   through ``try_put``/``try_get``/``full``/``empty`` never blocks and stays
   legal: the first cut refused it too, and the dataflow suite showed why
   that is wrong (the non-blocking probes in ``test_stream_ops_*`` and
   ``test_stream_nb_*``, and the self-FIFO S9/C1 tests, 13 tests). Only this
   rule: single-producer-single-consumer is not applied to plain regions. An
   annotation that cannot be evaluated at the definition is not checked. Two
   tests change with it: ``test_sim_timeout`` built its deadlock from a
   stream nobody puts to -- now refused at the region, which is the point of
   E1 -- and deadlocks on a two-kernel token cycle instead (the watchdog it
   tests is unchanged); ``test_stream_nb_simple`` declared a stream it never
   used, which is dropped.
``[Pass] Lower a bit slice that keeps its word's width without a same-width trunci``
   E5/E4. ``lowerGetSliceOps`` truncates only to a narrower result and
   zero-extends to a wider one.
``[Backend] Give a function that returns its scalar argument an output port``
   E3. Before emission, ``HLSModule`` puts a same-type
   ``unrealized_conversion_cast`` between a returned scalar argument and the
   return (``materialize_returned_arguments``, on the emission copy, after
   the lowering passes); every emitter prints it ``*out = v;``. One place for
   all the HLS emitters, rather than three signature emitters.
``[Backend][SystemC] Declare a constant array that a helper function reads at file scope``
   A2. Each constant global a helper reads is emitted once at file scope
   before the helpers (``emitStaticConstGlobal``, the code the kernel path
   already used); a kernel reading the same global uses that copy.
``[Backend][SystemC] Emit a helper's read-only array parameter const``
   A4. A helper's array parameter that is only loaded from, or passed to a
   helper parameter that is itself read-only, is emitted ``const T v[...]``
   (the new ``isConstArrayParam`` hook of ``emitFunctionSignature``; false
   for Vitis, so its emission is unchanged).
``[Backend][SystemC] Stop the csim testbench only after the DUT is done when memories are read out``
   A5. When a design has memory outputs as well as stream outputs, the last
   sink waits for the DUT's ``done`` and settles in-flight writes for the
   same cycles the memory-only path does, then stops. A design that never
   asserts ``done`` now reports ``TB DEADLOCK`` (the message names the
   wait) instead of reading half-written memories. Stream-only testbenches
   are unchanged.
``[Backend][SystemC][Catapult] Size ac_int bit slices by their bounds, not by the value's type``
   E2. With constant bounds, ``set_slc`` writes ``ac_int<hi - lo + 1>`` when
   the value is wider, and a get-slice narrower than its result is taken at
   its own width and zero-extended (as the LLVM lowering does). Residual,
   noted: with non-constant bounds both still use the type's width (the
   builder narrows the value itself there when it can, as in every case
   seen); a value *narrower* than a constant slice still writes only its own
   bits (pre-existing; the LLVM lowering zero-extends).

Draft upstream issue (A3)
-------------------------

    **[Bug] A user symbol whose name starts with `gelu`, `layernorm` or
    `tril` is deleted or replaced by the library op**

    `decompose_library_function` (`allo/passes.py`) recognises the library
    ops by prefix: every module-level op whose `sym_name` starts with
    `gelu`/`layernorm`/`tril` is erased, and every call to a callee starting
    with them is replaced by the template body::

        import numpy as np, allo
        from allo.ir.types import int32

        ROM = np.arange(64, dtype=np.int32)

        def kernel(A: int32[8]) -> int32[8]:
            gelu_tab: int32[64] = ROM
            B: int32[8] = 0
            for i in range(8):
                B[i] = gelu_tab[A[i]]
            return B

        allo.customize(kernel).build()
        # 'memref.get_global' op 'gelu_tab' does not reference a valid global memref

    A user function `tril_rows(A: int32[8]) -> int32[8]` called at the top
    of a kernel body is replaced by `tril` (`'linalg.yield' op type of
    yield operand 1 ('f32') doesn't match the element type`).

    Fix: the builder declares a library call as a bodiless private
    `func.func @<op>_<abs(hash(node))>`; match exactly that (external, name
    `^(gelu|layernorm|tril)_\d+$`) and replace only calls to those. A patch
    with tests is on `sunwookim028/allo` branch `core-fixes-3`.

Draft upstream issue (E5)
-------------------------

    **[Bug] `lower_bit_ops` emits `arith.trunci iN -> iN` for a bit slice
    whose result has the word's width**

    `lowerGetSliceOps` (`LowerBitOps.cpp`) ends every `allo.get_slice` with
    `arith.TruncIOp` to the result type. A slice whose result type equals
    the input width -- a full-width slice, or one whose bounds only become
    constant after `meta_for` expansion, which the builder types with the
    word's width -- gives `'arith.trunci' op operand type 'i32' and result
    type 'i32' are cast incompatible`::

        import numpy as np, allo, allo.dataflow as df
        from allo.ir.types import int32, UInt

        @df.region()
        def top(A: UInt(32)[4], B: int32[4]):
            @df.kernel(mapping=[1], args=[A, B])
            def k(a: UInt(32)[4], b: int32[4]):
                for i in range(4):
                    w: UInt(32) = a[i]
                    lane: int32 = w[0:32]
                    b[i] = lane

        df.build(top, target="simulator")   # trunci i32 -> i32

    Fix: truncate only when the result is narrower; zero-extend when wider.

Draft upstream issue (E1)
-------------------------

    **[Bug] A dataflow region accepts a Stream with no writer or no reader**

    A `Stream` declared in a `@df.region()` that no kernel uses builds and
    runs; one that a kernel only puts to builds (and blocks once full), and
    the HLS emitters emit it. Nothing counts a stream's endpoints across the
    region's kernels (`dataflow.py` records each kernel's direction only)::

        @df.region()
        def top(A: int32[8], B: int32[8]):
            orphan: Stream[int32, 4]
            @df.kernel(mapping=[1], args=[A, B])
            def k(a: int32[8], b: int32[8]):
                for i in range(8):
                    b[i] = a[i] + 1
                    orphan.put(a[i])

        df.build(top, target="simulator")   # builds; nobody reads `orphan`

    Proposal: at the region, refuse a stream that has no writing or no
    reading kernel, naming it. The fork's patch (branch `core-fixes-3`) does
    this from the region's AST, counting `put`/`try_put`/`full` and
    `get`/`try_get`/`empty` in every nested kernel.
