1. The merge (``da96e3d2``)
===========================

``git merge --no-ff pr48-head`` into ``u1-pilot``: **three** one-hunk
conflicts, not the two the probe saw against ``main`` ``9b33ee03``. Each was
resolved by keeping both sides:

- ``allo/backend/simulator.py``: the PR's stream-aware ``ext_libs`` loop
  (``compile_shared_lib(stream_sim=True)`` for stream IPs), then
  ``self._shared_libs = shared_libs`` (kept for ``reset()``). As in the probe.
- ``allo/dataflow.py``: the ``!allo.wire``/``!allo.channel`` refusal, then the
  PR's ``LLVMOMPModule(s.module, s.top_func_name, s.ext_libs)``. As in the probe.
- ``allo/passes.py`` (new against ``u1-pilot``): ``u1-pilot`` adds
  ``materialize_returned_arguments`` directly above ``call_ext_libs_in_ptr``,
  where the PR adds ``_nested_ops``; kept ``materialize_returned_arguments``,
  then the PR's ``_nested_ops`` and ``call_ext_libs_in_ptr(...,
  allow_stream_ip=False)``.

2. The follow-up (``1d75b012``)
===============================

- **validate_rtl on Verilator 5**: ``--json-only`` instead of ``--xml-only``,
  from the probe's patch, with one change: the top is the ``MODULE`` with
  ``level == 1`` *and* ``origName == top`` (the probe matched ``origName``
  only, which a parameterised submodule could share). ``xml.etree`` import
  dropped.
- **verilator_args** on ``RTLModule`` (list, or one string split with
  ``shlex``), appended to the ``--json-only`` run and the ``--cc --build``
  run; passed on to the generated adapter's inner ``RTLModule``.
- **max_stall** on ``RTLModule`` (positive int, default 500000), emitted as
  the transactor's ``MAX_STALL``; passed on to the adapter too.
- **Verilator binary**: ``verilator=`` / ``$VERILATOR`` / ``PATH`` was already
  the PR's order; now documented in the class docstring, the docs page and
  ``dev/toolchains.rst`` (RTLModule paragraph beside the 5.052 pin).
- **Docs**: ``docs/RTL_MODULE.md``, ``docs/IP_STREAM_INTEGRATION.md``,
  ``docs/IP_STREAM_SIM_SHIM.md`` -> ``docs/source/backends/rtl_module.rst``
  (in the Backends toctree; content kept, converted by a small script, plus
  "On this fork": Verilator 5, the two knobs, the probe's limits, the
  ``vitis.py`` ``depth=`` and ``-pipeline_loops 0`` side effects, the wiring
  check). Markdown files deleted; references in ``allo/``, ``tests/``,
  ``examples/ip_integration/`` updated; CLAUDE.md fork-pages row added.
  ``sphinx-build -b html -D plot_gallery=0``: 0 warnings for the page (the
  first conversion had 4 bold/literal nesting warnings, fixed).

Two things the task did not list, both found by the gates:

- **The region wiring check refused every stream-IP region.** ``u1-pilot``
  (and ``main`` since ``6de9b8eb``, which is *not* in the probe's
  ``9b33ee03``) refuses a plain-kernel region's stream with one blocking end
  only (``allo/ir/units.py``, ``_check_kernel_streams``). It only scanned
  ``.put/.get/...`` method calls, so ``ip(a, c)`` was not a use: **14 of the
  PR's tests failed** with ``NetlistError: unconnected-stream`` (first run of
  the suite on the merge: 14 failed, 48 passed, 1 skipped). Fixed by
  ``_ip_stream_uses``: a call to a name that resolves to an object with
  ``has_stream_args`` makes the kernel a reader of the streams in its
  ``input_idx`` and a writer of those in ``output_idx`` (blocking, like
  ``get``/``put``). Two PR tests (``test_signedness_mismatch``,
  ``test_multiple_static_calls_rejected``) built regions whose streams had
  only the IP's end; they now get a ``feed``/``drain`` kernel, since the
  refusal is correct for them. New test ``test_one_ended_ip_stream_refused``.
- **TinyTPU's ``cosim.py`` would have emitted two ``depth=``.** The PR's
  ``vitis.py`` now emits ``depth=<static element count>`` on every ``m_axi``
  pragma of a ``vitis_hls`` project; ``patch_axi_depths`` appended its own,
  giving e.g. ``bundle=gmem0 depth=56 depth=56`` (values equal: 56, 4096 x 3).
  It now replaces an existing ``depth=``. ``csynth_sweep.py``,
  ``parity_sweep.py``, ``act/measure.py``, ``act_cosim.py``,
  ``impact/cosim_variant.py`` and ``export_rtl.py`` call the same function.

New tests: ``test_verilator_args_and_max_stall`` (no Verilator),
``test_verilator_args_reach_verilator`` (an unknown option must fail
``validate_rtl``), ``test_one_ended_ip_stream_refused``.

5. Differences from the probe's expectations
============================================

- **Three conflicts, not two** (``passes.py``; ``u1-pilot`` is not ``main``).
- **The JSON port alone was not enough on this base**: the wiring check
  (``6de9b8eb``, newer than the probe's base) refused 14 of the PR's tests
  until IP calls were counted (section 2). ``main`` has that check too, so a
  merge of #48 into ``main`` needs the same fix.
- **The ``vitis.py`` ``depth=`` change does reach TinyTPU**, through
  ``cosim.py``: not through the hashed emissions (``vhls``/``catapult``/
  ``systemc``, unchanged) but through the ``vitis_hls`` project cosim builds.
- Test count 63 rather than 60: the three new tests.
- **TinyTPU cosim does not run on zhang-21 as committed, on any branch.**
  ``cosim.py`` links with ``-ldflags "-B/usr/bin"``; here ``/usr/bin/ld`` is
  binutils 2.30 (RHEL 8), which cannot read the objects Vitis 2023.2 compiles
  (``unable to initialize decompress status for section .debug_info`` ...
  ``file not recognized``), so every shape ends with "no TB line". Same
  failure on ``main`` ``552db66a``, with gcc-toolset-13 on ``PATH`` or not.
  With ``TCL_COSIM``'s ``-B`` replaced by ``/opt/rh/gcc-toolset-13/root/usr/bin``
  (ld 2.40), done from a ``python -c`` wrapper, not committed, cosim passes
  -- but at **222 / 361 / 567 / 676 / 868** cycles, not the published
  175 / 265 / 421 / 482 / 674, on ``main`` exactly as on this branch. So the
  PR changes nothing in cosim (same ``kernel.cpp`` byte for byte); the gap to
  the published numbers is this host's toolchain path, or something on
  ``main`` since they were published, and is not this branch's to settle.
  **Superseded by section 6:** the gap is ``TPU_MAXDIM`` (64 here, 16 in
  ``reproduce.sh``), not the host.
- ``test_region_stateful.py`` as a script is a no-op (no ``__main__``); its
  pytest run is the meaningful gate. Worth fixing in CLAUDE.md's golden-test
  recipe separately.

Not run: ``mutate.py`` (the ``cosim.py`` change touches only the pragma
rewrite, which no mutant targets; the cosim run above exercises it, and
cosim is not usable here as committed anyway),
``TPU_TB=stress`` cosim, ``test_stream_ip_csynth`` (vendor synthesis, as the
PR's own README deselects it), lint beyond ``black`` on changed Python files.

**Cause of 222 vs 175: the array size.** ``reproduce.sh`` exports
``TPU_MAXDIM=16`` (the configuration the published counts were measured at);
``cosim.py`` run directly with no ``TPU_*`` set builds at ``microarch_isa.py``'s
default ``MAXDIM=64``, and section 5's runs printed exactly that
(``ONE build -- 4x4 array, MAXDIM=64``). Bisect: ``TPU_MAXDIM=16 python
cosim.py`` alone, fresh project, no linker override -> 175 / 265 / 421 / 482 /
674, COSIM OK. The linker override in section 5 changed nothing (u1-pilot's
``linker_dir()`` now does the same thing by default), and the PR changes
nothing in cosim. Note: ``stress_isa.py`` gives 492/492 under
``reproduce.sh`` (MAXDIM=16: 64 GEMM shapes) and 640/640 in section 3
(MAXDIM=64: 96 shapes), for the same reason.
