4. Finding: ``harness/calendar.py`` shadows the stdlib under the script form
============================================================================

``examples/minitpu/harness/calendar.py`` (``u4-phase0``, commits
``4faf7e86`` / ``7784c950``) is run as ``python -m
examples.minitpu.harness.calendar``. Running ``python
examples/minitpu/harness/check.py <unit>`` -- the form sync 3 and
``u2_comb_wire_impl_2026-10-02.rst`` use -- puts ``harness/`` first on
``sys.path``, so ``import pandas`` -> ``_strptime`` imports this file as
``calendar`` and every unit dies at import (``AttributeError: module
'calendar' has no attribute 'day_abbr'``, 3-4 s, all five units). The
``-m`` form used by most records is unaffected and gives
the verdicts above. Fix: rename the module (e.g. ``wb_calendar.py``). Not a
blocker for the fast-forward; to be filed as a fork defect.

* **reproduce.sh on the baseline was not run.** It runs ``ninja -C
  mlir/build -j $(getconf _NPROCESSORS_ONLN)`` and writes
  ``examples/tinytpu/.scratch``, and ``ninja -n`` on the main checkout's build
  reports 25 pending steps (archive relinks: ``libMLIRAlloConversion.a``

  baseline's build. Its five stages are the gates above, run individually
  on both sides. The same perpetual relink shows on the fresh branch build
  (31 relink steps on each ``reproduce.sh`` run, 22 still pending after): a
  build-tree quirk, not a source change.
* The first branch ``reproduce.sh`` attempt (exit 1, 59 s) was a wrapper
  artefact: sourcing ``env-zhang21.sh`` puts Catapult's ``bin/`` (its own
  python, no numpy) first, and the script's ``python`` resolved to it. Rerun
  under the plain ``allo`` env as CLAUDE.md prescribes: pass.
* ``python tests/dataflow/test_region_stateful.py`` has no ``__main__`` block,
  so running it as a script executes no test (exit 0, no output, both sides).
  Its 8 tests ran under pytest and pass on both sides. CLAUDE.md's golden-test
  line for it checks nothing as written.
* Vitis cosim is not counted: it does not link on this host (system ``ld``
  2.30; ``tinytpu-instance`` finding F13).
* The full ``mutate.py`` run was not repeated (optional; >480 s under load);
  ``mutate.py none`` passes on both sides and the ``vadd_holds_stale_x``
  anchor fix is in the branch.
