What "cycle" means in each column
=================================

The command trace is the U2 Phase 0 one: every ``traces("w16")`` trace and
the ``tb_vpu_alu_regfile`` seed **joined end to end** (60,261 cycles; w256:
15,249). Joining matters for the mask census: the regfile is never reset, so
after the first trace every register is written and only **3** slots are
undefined (``uninit``), against 484 when each trace runs from power-on
(Phase 0). The responses are compared on the 180,780 defined slots (w256:
45,744).

* **Allo simulator**: untimed. Cycle ``t`` is iteration ``t`` of the unit's
  loop, so the check is an *order* check: the three reads of ``t`` see every
  write before ``t`` and not the write of ``t``. That is exactly the RTL's
  "read old on same-cycle write, write visible next cycle".
* **SystemC csim**: values per iteration; the time a value appears is not
  checked (the arrays become Connections streams; csim cycles are the
  handshakes', ``u1_pipe``).
* **Catapult RTL** (``wire`` variant, Wire ports = plain ``sc_in``/``sc_out``):
  driven per clock by the harness ``trace`` shape with MiniTPU's own command
  trace, and compared per clock. Read latency and write visibility are
  measured on the RTL (step probes, and the output offset at which every
  defined slot agrees).
* **RTLGen / AMC**: array ports (``A_rd0_*``), so per-iteration values and a
  total cycle count; the port timing of one access is not observable.

Variants (``examples/minitpu/units/vpu_regfile.py``)
====================================================

All take one array per RTL input port (``UInt(5)`` addresses, ``UInt(W)``
data, ``uint1`` we) and return one per read port, from the same trace.

=================  =======================================================================================
variant            expression (plan id)
=================  =======================================================================================
``trace``          R1: one kernel, kernel-local ``mem: UInt(W)[32]``; per iteration 3 reads then the write
``trace_raw``      ``trace`` as first written, without the B4/S6 workarounds (evidence only)
``stateful``       R2: ``mem @ Stateful``; the trace fed in 1,024-cycle chunks over calls of one module
``ported``         R3: ``@df.unit`` with 6 command + 3 response ``Stream`` ports, lockstep; driver/sink kernels
``shared``         R4: region-scope ``@ Stateful`` regfile, 3 reader kernels + 1 writer kernel, nothing else
``shared_sync``    R4 + explicit per-cycle order: token streams reader->writer ("read t done") and back
``annotated``      R5: ``trace`` + ``@ Memory(resource="LUTRAM", storage_type="RAM_1WNR", latency=0, depth=32)``
``wire``           ``trace``'s body with ``Wire`` ports, unit kernel ``rf_0`` (the Catapult port shape)
=================  =======================================================================================

R6 (port-server kernels) was not built: R4 with ``shared_sync`` already is the
"one kernel per physical port" shape, and the conflict probe it was for (plan
2c ii) has nothing to probe in this unit (one write port by construction;
H11 below).

Findings
========

Each has a minimal repro in ``u2_regfile_2026-10-02/repros.py`` (output in
``logs/repros.txt``) unless noted.

**B4 (Allo core, bug, silent; high).** An unsigned array index is
sign-extended on the simulator/LLVM path: ``allo/ir/builder.py:569`` maps
``(UInt, Index)`` to ``arith.IndexCastOp`` (signed) instead of
``IndexCastUIOp``. ``mem[ra[t]]`` with ``UInt(5)`` 20 reads ``mem[-12]``; a
``uint8`` index of 200 reads ``mem[-56]``. Repro: ``uint8 [1,200,255,128] ->
[1,1,0,0]``. The regfile ``trace`` variant *matched* as written, because 16..31
alias 32 distinct out-of-bounds words consistently; the same expression on a
region-scope global segfaulted (``shared_sync``). The HLS C++ emitters are not
affected (``ap_uint`` index). *Proposed fix:* ``IndexCastUIOp`` for
``(UInt, Index)`` and ``(Index, UInt)``, with the B1 tests' pattern. Same
family as B1 (signedness read off a signless type); anything indexing by an
unsigned value at or above half its range is wrong in the simulator today.

**B5 (Allo core, bug, loud).** ``x: int32 = s.get()`` on a
``Stream[UInt(5)]`` stores the ``i5`` into an ``i32`` memref with no cast;
the verifier refuses (``'affine.store' op value to store must have the same
type``). Workaround: ``a5: UInt(5) = s.get(); a: int32 = a5``.

**S6 (SystemC emitter, bug, silent).** An argument array read under a
condition becomes a conditional ``Pop()`` on the Connections stream the
array is turned into, so the stream falls out of step with the loop:
``if we[t]: mem[wa[t]] = wd[t]`` pops ``wa``/``wd`` only when ``we``.
``trace_raw`` csim: 1,266/180,780. Repro (6 elements): simulator
``[10,10,10,13,13,15]``, csim ``[10,10,10,11,11,12]``. *Proposed fix:* the
stream conversion must refuse (or hoist) an argument access that is not
executed exactly once per iteration, as e238e410 refuses a written-and-read
array.

**B6 (simulator, bug, silent corruption).** A numpy array narrower than the
kernel's element type (``uint64`` for ``UInt(256)``) is accepted with an
``Input type mismatch`` *warning* and read past its end (repro: SIGABRT at
n=4; at the regfile: heap corruption and a hang). *Proposed fix:* refuse a
narrower dtype (D-1), and say how to pass > 64-bit elements -- today there is
no way to (H8).

**S7 (SystemC emitter, bug, loud).** The emitted csim testbench reads and
writes every port through ``long long``: at 256 b Catapult refuses the
``kernel.cpp`` it is given (``no suitable conversion function from
ap_uint<256> to long long``, CRD-413), because the TB is in the file it
compiles even when ``synth_top`` is the unit; csim fails at read-back
(``KeyError 'ui256'``, S5's class). Hand-patch for Catapult:
``catapult/wire_part_w256_n64_3p33/hand_patches.diff`` (``.to_int64()``; the
TB is not synthesized). *Proposed fix:* wide ports through a word-split file
format, and the TB under ``#ifndef __SYNTHESIS__``.

**M1 (semantic mismatch): ``@ Stateful`` across calls.** The simulator keeps
a Stateful across calls of one module (the documented contract). SystemC csim
starts a new process per call and runs the reset action, so the state is
reinitialised (``stateful`` csim 170,093/180,780); RTLGen's ``cosim()``
re-instantiates the RTL per call (179,534/180,780). In RTL the contract is
"between resets" -- which no column can test across calls today.

**M2 (semantic mismatch, simulator): shared Stateful without order.**
``shared`` gives 8,502/180,780 with no diagnostic: four kernels share the
array and nothing orders them, so the readers finish before the writer
starts (deterministic in two runs, not guaranteed). The RTL's order is the
clock; Allo can state it only as explicit token streams (``shared_sync``,
which matches). SystemC refuses both, correctly.

**G1 (missing abstraction): one memory, several ports.** The regfile is
expressible only as *one kernel that owns the array* (``trace``/``ported``/
``wire``). "One memory, three read ports and one write port, used by
different state machines" -- the shape U2 is about -- is refused by SystemC
(region Stateful and region-argument sharing both), refused by ``compose``,
honoured unordered by the simulator (M2), and nowhere can a port count or a
port latency be stated. RTLGen and AMC each *infer* ports (RTLGen: a
write-broadcast replica; AMC: 5 logical ports on 2 physical) but neither
lets the user state them. This is the plan's "``compose`` declares memory
ports" item; the regfile is its first concrete case.

**G2 (missing abstraction): asynchronous read (H4).** No generated RTL can
read in the cycle of the request. Catapult: read latency 1, write->read 2,
measured, on both clocks and both widths -- a uniform one-edge shift, so the
relative order (read old on same-cycle write; write visible next) is
preserved. RTLGen and AMC: registered reads (``mem_c0_rd0_reg``; ``r(1)``).
The ``Wire`` port shape does not help: a ``sc_in`` read is not a schedulable
op (U1 N2).

**H5/W1 (workaround): complete partition.** Catapult's default mapping of a
32-entry array is a 1R1W sync RAM, which cannot serve 3 reads + 1 write per
iteration (SCHD-30). Allo's own ``s.partition(..., Complete)`` fixes it, and
the emitter translates it into a Catapult directive -- the correct D-1
behaviour for that directive. The same partition gives RTLGen II=1 and
blocks AMC.

**D-1 sweep of ``Memory(...)`` (H3, bug by D-1).** ``Memory(latency=0,
depth=32)`` never reaches the IR (``memref<32xi16, 52 : i32>`` carries only
resource x 16 + storage). SystemC/Catapult drops the whole annotation
(``kernel.cpp`` and ``run.tcl`` byte-identical with and without it). Vitis
keeps resource and storage only (``#pragma HLS bind_storage variable=mem
type=ram_1wnr impl=lutram``, no ``latency=``). Nothing refuses.

**Minor.**

* The simulator does not refuse ``Wire``: the build reaches LLVM translation
  and stops with ``missing LLVMTranslationDialectInterface registration ...
  func.func`` (loud, but not a refusal naming the construct).
* The simulator aborts or segfaults *at exit* after some runs (``ported``,
  ``annotated``): the known OMP-at-exit pitfall; results were complete.
* Catapult builds into ``Catapult_1/`` when a previous failed run left
  ``Catapult/``; scripts that hard-code ``Catapult/<top>.v1`` read stale or
  missing RTL.

What the owner must decide before the rest of U2
================================================

1. **B4 now.** One line in ``builder.py``, silent, and it touches every
   unsigned index at or above half its range in the simulator -- U1 units,
   TinyTPU and MiniTPU programs included. *[fix on a ``core-*`` branch with
   tests, check TinyTPU gates and U1 verdicts unchanged, as for B1]*
2. **S6, B5, B6, S7.** *[S6 refusal in the emitter first (silent); B6 refusal
   in the simulator; B5 and S7 with their tests]*
3. **Async read = latency 1 (triage 4 extended to ports).** Catapult measured
   a uniform one-edge shift that keeps the read/write order. Accept as a
   recorded deviation, so ``vpu_regfile``'s Catapult cell is "match at L=1"?
   *[yes; the ports' declared latency becomes part of the latency proposal,
   triage 8]*
4. **Stateful across calls (M1).** Define it: persists until reset, and
   csim/cosim reset per call, or csim/cosim keep one process across calls?
   *[for U2 verdicts, single-call variants only (``trace``, ``ported``,
   ``wire``); M1 to limitations]*
5. **Memory ports (G1, plan Q8).** U2's remaining shared-memory units
   (``vpu_word_array``'s two ports) hit the same wall. Approve drafting the
   D-n for "``compose`` declares memory ports", with RTLGen's write-broadcast
   replica as the SystemC lowering for N read ports?
6. **``Memory(latency=, depth=)``.** Refuse the fields a backend drops (D-1),
   or implement them (SystemC: Catapult ``-STAGE_REPLICATION``/latency
   directives)? *[refuse now; implement with item 5]*
7. **Expressions for the rest of U2.** *[R1 ``trace`` as reference, R3
   ``ported`` for the composition track, ``wire`` + partition for Catapult;
   ``stateful`` and ``shared`` stay as probes, not verdict variants]*
8. **Joined traces.** One joined trace masks 3 slots instead of 484. Keep
   joined (one build per column, as here), or run the power-on traces
   separately for the undefined-slot census? *[joined for verdicts; Phase 0
   keeps the census]*
