U2: a combinational (same-cycle) read for ``vpu_regfile``
###########################################################

.. note::

   **Dated measurement record, 2026-10-02.** zhang-21, branch
   ``u2-comb-read`` (from ``origin/u1-pilot`` at ``bf0e60ab``); bindings a
   private copy of ``wt-u1``'s build (``ldd`` resolves
   ``libAlloMLIRAggregateCAPI`` inside the worktree). MiniTPU at
   ``b3ba0a4d``, read only. Catapult 2024.2 (``nangate-45nm_beh``), DC
   W-2024.09 (FreePDK45, the U1 flow, ``dc_u1.tcl`` byte-identical),
   Verilator 5.052. Nothing under ``allo/`` or ``mlir/`` changed: the emitter
   change is a hand patch on Allo's own emission, recorded as a proposal.
   Scratch (Catapult and DC projects, not kept): ``scratch/u2cr/``.

The U2 pilot (``u2_regfile_2026-10-02.rst``, G2) measured every generated
RTL of the regfile at read latency 1 and write->read 2 against MiniTPU's 0
and 1, and offered "async read = latency 1" as a recorded deviation. The
owner chose instead to pursue a true combinational read. This record is
that pursuit: which forms Catapult accepts, what each one measures, and
what Allo's SystemC emitter would need.

**Result.** Catapult produces RTL whose three read ports return *this*
cycle's array contents (read latency 0 in the harness's edge count, write
visible after 1 edge), **bit-exact on every defined slot** of the joined
trace against ``vpu_regfile.sv`` (w16 180,780/180,780 at 2.0 and 3.33 ns;
w256 45,744/45,744), from a SystemC module with **one clocked thread for
the write and one ``SC_METHOD`` for the reads over an array of
``sc_signal``**. Applied as a 121-line hand patch to Allo's own emission of
the ``wire`` variant it gives the same result. DC same-flow area is 4,451
um^2 against MiniTPU's 4,022 (+10.7 %; the pilot's latency-1 form was
+45.8 %). G2 is therefore amended: the missing abstraction is Allo's, not
the tool's. Nothing in Allo expresses it today; the proposal is at the end.

What "latency" means here
=========================

The harness ``trace`` shape (``harness/rtl.py``): cycle ``t`` drives row
``t`` with the clock low, ``eval()``, samples the outputs ("pre"), then the
rising edge ``t + 1`` ("post"). ``cmp_rf.py`` measures the read latency as
the output offset L at which the defined slots of the first 3,000 cycles
agree: L = 0 is the "pre" sample of the same cycle -- an asynchronous read,
MiniTPU's -- and L >= 1 the "post" sample of row ``t + L - 1``. Then every
defined slot is compared at that L, and the regfile's own step probes
(``units/vpu_regfile.py`` ``probes``) are run on both RTLs: MiniTPU reads
at 0 and shows a write to a read 1 edge later.

from ``catapult/<form>/csyn.log.gz``.

Like for like is now MiniTPU itself. At w16 d1's combinational area equals
MiniTPU's (+1.3 %: the same three 32:1 muxes); the sequential +16.7 % is
the reset: MiniTPU's storage flops have no reset (``DFF_X1`` in
``reference.rpt``), Catapult's are asynchronously reset (``DFFR_X1``, the
cell DC maps CIN-233's reset action to), plus the thread's input registers.
At w256 the generated design is **smaller** than MiniTPU's: DC builds
Catapult's ``mgc_mux1hot`` read trees in 23,362 um^2 of logic where it
infers MiniTPU's ``assign rdata = mem[raddr]`` in 45,567; the sequential
side is again the reset flops (+17.6 %). Both close 3.33 ns with the same
slack (1.96 / 1.95).

Findings
========

**F1 (Catapult, match; amends G2).** A SystemC module with an ``SC_METHOD``
over ``sc_signal`` storage synthesizes to a clockless read block
(``rf_comb_comb``: addresses and the 32 register outputs in, data out; 0
``posedge`` in it) beside a clocked write thread, and its ports behave as
MiniTPU's: read 0, write->read 1, bit-exact on every defined slot at both
widths and both clocks. G2's "no generated RTL can read in the cycle of
the request" is wrong for Catapult; it is right for everything Allo emits
today (every ``sc_out`` an ``SC_THREAD`` writes is registered at the next
edge: b2, c, a1b, and the pilot, all L=1) and for RTLGen and AMC (below).

**F2 (SystemC emitter, missing abstraction; the proposal).** Allo has no
combinational process form. ``Wire`` ports are plain ``sc_in``/``sc_out``,
but every kernel is one ``SC_THREAD`` with a ``wait()`` per iteration
(``EmitSystemC.cpp:1785``, ``:1101``), so a ``Wire`` output is a register.
The hand patch (``catapult/e_wire_patch/hand_patches.diff``) is exactly the
emitter change, on the emitted names:

1. **Storage read by the combinational cone becomes an array of
   ``sc_signal<T>``** (``sc_signal< ac_int<16, false> > mem[32];`` as a module
   member), accessed through ``.read()``/``.write()``, and **zeroed in the
   reset action** (CIN-233; F3). A plain member array -- the current
   ``@ Stateful`` emission -- is refused by Catapult for an ``SC_METHOD``
   (CIN-197, d2). This also removes the pilot's H5 workaround: an
   ``sc_signal`` array is registers by construction, so no
   ``s.partition`` / ``hls_resource [Register]`` is needed (d1 has no
   ``MEM-74`` and needs no map).
2. **One ``SC_METHOD(comb)`` per kernel**, sensitive to the ``Wire`` inputs
   it reads and to every storage signal, holding the ``Wire.put`` cones that
   qualify; the ``SC_THREAD`` keeps the state updates, the other ``Wire``
   reads and its ``wait()``.
3. **The qualifying rule** (what the emitter would classify): a
   ``w.put(e)`` whose cone contains only ``Wire.get()``\ s and loads of a
   kernel-local or ``Stateful`` array, with **no store to that array
   earlier in the same iteration** in program order. That is the
   regfile's "reads then write" body; a write-first body would read new
   data through a combinational path and must stay in the thread (or be
   refused with the reason). The simulator's semantics do not change: it
   already runs the body in that order.

Expression options for the owner: (i) **automatic** -- apply the rule to
every ``Wire``-port kernel, so the pilot's ``wire`` variant as written
becomes L=0 (no new syntax; the risk is a silent latency change on
existing Wire designs, so it should at least be reported in
``latency.json``); (ii) **explicit** -- a marker on the output port or the
kernel (``Wire[T, comb]`` or ``@df.kernel(comb=True)``), refused when the
rule fails. Either keeps D-11: it is one kernel, one ``Stateful``. (ii) is
the D-1-safe default. ``latency.json`` (D-10) then needs a rule for a port
driven by an ``SC_METHOD``: ``port_style: wire-comb, latency: 0``, checked
on the RTL as here (the CCORE case in ``latency_report_2026-10-02.rst``
already asks for ``port_style: comb``).

**F3 (Catapult, semantic mismatch, recorded).** Catapult requires every
``sc_signal`` to be written in the reset action (CIN-233, d1-nr), so the
generated storage is cleared by ``rst``; MiniTPU's is not ("never reset
(would block LUTRAM inference)"). The trace comparison holds ``rst`` high
on the generated side (as the pilot did), so the ``reset-keeps`` directed
trace does not exercise this; it would differ. Cost: ``DFFR_X1`` instead of
``DFF_X1`` on 512 flops (the +16.7 % sequential area). A storage without
reset is not expressible in Catapult SystemC; ``ALLO_SYNC_RESET`` would
only change the flop type.

**F4 (Catapult, limit; shapes the proposal).** CIN-197: a combinational
process may be sensitive only to signals and ports; a member variable
written by a thread cannot feed it (d2). So any state an ``SC_METHOD``
reads must be ``sc_signal``; the emitter's ``@ Stateful`` member form
stays for state read only by its own thread.

**F5 (Allo core, bug, loud).** ``s.partition("rf_0:mem", Complete)`` on a
``@ Stateful`` array crashes: ``allo/ir/transform.py:161``
``search_operations_recursive(op.else_block.operations)`` --
``AttributeError: 'NoneType' object has no attribute 'operations'``
(``find_buffer`` walks the kernel's ``scf.if`` without an else block; the
``if we:`` store). Repro: ``emit_csyn.py vpu_regfile wire_stateful ...
--partition rf_0:mem`` (``logs/b_partition_crash.txt``). *Proposed fix:*
guard the else block (``if op.else_block is not None``) in
``search_operations_recursive``; whether the global is then found is
untested.

**F6 (Catapult, info).** A ``#pragma hls_design ccore`` +
``hls_ccore_type combinational`` function called from a SystemC process is
inlined (HC-8, CIN-14), not built as a block; the clockless CCORE of
``latency_report_2026-10-02.rst`` section C works only as the C++ top.
Inside a SystemC design the process type, not a CCORE marker, decides the
read latency (a1b = L=1, a2 = L=0, same mux function).

**F7 (csim, limitation 22, unchanged in kind).** The patched kernel compiles
and runs under the emitted testbench; the per-port skew against the
reference drops by one cycle (+3/+2/+2 from +4/+3/+3) because the comb
read no longer costs a delta of the thread. The src/sink kernels are still
free-running threads.

**RTLGen and AMC: no clockless read (checked once, from the code).**
RTLGen adds ``clk``/``rst``/``start`` to every module unconditionally
(``mlir/lib/allo/Microarch/Primitives.cpp:60-62``, ``kDone`` at ``:91``),
drives ``done`` through the sibling composition of regions
(``HWEmitter.cpp:643-655``), and its ``done`` is a latch of one cycle
(``include/allo/Scheduling/LatencyModel.h:38``, ``kDoneLatchCycles = 1``).
Its ``RegisterFile`` interface does read a fully partitioned *argument*
"combinationally in any number at once" (``Primitives.cpp:84-89``), but
that is the input side of a clocked module whose outputs are registered:
the pilot measured ``mem_c0_rd0_reg``. AMC gives every top ``clk``/``rst``/
``start`` and ``ready``/``done``
(``circt/lib/Conversion/LoopScheduleToFSM/LoopScheduleToFSM.cpp:3682-3690``,
``:8301-8322``) and registers every pipeline-stage output as a
``seq::CompRegClockEnabledOp`` (``:10686-10697``). Neither has a process or
port kind without a clock; both would refuse ``comb`` (D-10), as the
latency report concluded.
