The ``trace`` shape
===================

A stateful unit is a function from a *command trace* (every input port, reset
included, once per cycle) to a *response trace* (every output once per cycle).
``run_trace(unit, cmd, seed)`` takes ``{port: values}`` and returns
``{port: uint64[n, nwords]}``.

* **Sampling.** Cycle ``t`` runs in this order:

  1. drive row ``t`` with the clock low and ``eval()``;
  2. sample the ``"pre"`` outputs;
  3. take rising edge ``t + 1``;
  4. sample the ``"post"`` outputs.

  An output spec is ``(port, width, "pre" | "post")``. Asynchronous reads and
  flags are ``"pre"``, so a same-cycle read and write shows the old value.
  Registered reads are ``"post"``. A port of latency ``L`` edges shows a
  cycle-``t`` command in row ``t + L`` (pre) or ``t + L - 1`` (post), which
  matches U1's edge count.
* **Wide ports.** A port is ``ceil(w/64)`` little-endian ``uint64`` words in
  the raw files. The C++ driver copies them into and out of Verilator's
  ``VlWide`` (32-bit ``EData`` words) through overloaded ``setp``/``getp``.
  A port of 64 bits or fewer stays a scalar. Tested at 33, 64, 100, 256,
  257 and 1024 b.
* **Undefined state.** A trace build adds ``--x-initial unique``, and every run
  sets ``randReset(2)`` and ``randSeed(seed)``. ``characterize`` runs every
  trace with two seeds and requires every slot the reference calls defined to
  be **seed-invariant**. This catches a reference that calls something defined
  when the RTL leaves it open. The plan's [I] "confirm the flag's effect on
  unpacked memories" is **confirmed**: every ``uninit`` read moved with the
  seed, including the 4096 x 1024 b VMEM and the FIFO ``mem``.
* **Masks.** A reference returns ``(resp, reason, events)``. ``reason[port][t]``
  is ``""`` on a defined slot. Otherwise it names the cause, and the slot still
  holds the reference's guess of what the simulation model does. The census
  reports, per reason, the slot count, how many slots the guess matched, and
  how many moved with the seed. The census is evidence for the quirks (H12)
  without making them part of the contract.
* **Assertions.** With ``assertions=True`` the model is built with
  ``--assert`` and ``errorLimit(2^30)``, and the context time is the cycle.
  ``last_asserts`` lists every firing as ``(cycle, message)``. A trace tagged
  legal must fire none.
* **Probes.** ``probe_trace(unit, cmd, port, event)`` counts the edges from
  the command issued in cycle ``event`` to the first row where ``port`` moves.
  It uses no reference.
* **Reset.** Reset is an ordinary command port, so a trace resets mid-stream.
  ``reset=True`` keeps U1's 4-cycle prologue.
* **Mutation check.** A write-first mutant of the regfile reference gave
  REF-DIFF on the first directed trace, so the comparison can fail.

The reference models (``harness/ref.py``)
-----------------------------------------

**``vpu_regfile``.** A read returns the entry as it was before the cycle's
write (old value on a same-cycle read and write), and a write is visible one
cycle later. ``rst_ni`` does nothing: the directed ``reset-keeps`` trace
writes, holds reset 4 cycles, and reads the data back; a write under reset
lands. The only undefined slot is ``uninit``. Port C behaves like A and B.

**``vpu_word_array``** (the simulation model). An enabled port reads the word
as it was before the cycle, and the read leaves the pipe ``L`` edges later.
Writes are visible one cycle later from either port. The undefined slots, and
what the census measured for each:

* ``no read`` (``en`` low ``L`` cycles earlier). The pipe holds its last read:
  where the held word was defined, the guess matched every slot.
* ``write cycle`` (a same-port read-during-write). The guess is the old word,
  and it matched every slot whose old word was defined. **H12, simulation
  half: confirmed.** The XPM ``no_change`` half, where the output holds, needs
  an XPM simulation and is **not run** here.
* ``collision`` (a read of a word the other port writes in the same cycle).
  It returned the old word on every slot.
* ``ww collision`` (both ports write one word). It is masked until the word
  is rewritten. Measured: the **DMA write wins** in every case: 699 + 653
  slots (narrow), 75 + 75 slots (full). This is because the DMA
  ``always_ff`` comes after the compute one, so it is an artefact of the
  model's block order.
* ``uninit``.

**``vpu_fifo``.** Update rules:

* A push is taken if the FIFO is not full, or if it is full and a pop comes
  in the same cycle (pass-through).
* A pop is taken if the FIFO is not empty, or if it is empty and a push comes
  in the same cycle.
* A push on full with no pop is dropped, and the overflow assertion fires.
* A pop on empty with no push is ignored, and the underflow assertion fires.

Reset clears the pointers and the count, not ``mem``. The flags are defined
after the first reset, illegal traces included, so the reference is
bit-exact there too: this is F2's "bit-exact on illegal traces". The
``pop_data_o`` slots while empty matched the stale-entry guess in all
80,889 slots.

**H12 (FIFO half): confirmed.** A push and a pop on an empty FIFO move both
pointers, the count stays 0, ``pop_data`` that cycle is the stale
``mem[rd_ptr]``, and the pushed word is lost. **No assertion fires**: the
underflow assertion ``vpu_fifo.sv:40`` excludes ``push_i``. Counted: 2,785,
672, 2,195 and 2,645 events across the four instances, with 0 firings.

Findings
========

1. **asm's output-FIFO rule ignores loop trip counts** (MiniTPU, tier i).
   ``_check_matrix_fifo`` counts ``vmatpush``/``vmatpop`` in static program
   order. Measured: ``schedule()`` refuses 17 straight-line ``vmatpush``, but
   **accepts** ``loop.begin 17 { vmatpush }`` followed by 17 ``vmatpop`` (21
   bundles). 17 groups against a 16-entry FIFO drop one at the RTL; see the
   ``vpu_fifo:output`` ``overflow`` trace. The plan lists the rule
   as a refusal without this limit.
2. **``vmatpop`` with nothing pushed is neither refused nor asserted.**
   Measured as accepted (2 bundles). The plan's conflict list does not
   mention it.
3. **H12 FIFO half confirmed, and stronger than the plan says**: a push and a
   pop on empty loses the word with **no** assertion, which contradicts
   ``vpu_fifo.sv:5`` ("simulation asserts"). Neither MXU instance can reach
   it (rows 13 and 14), so it is latent.
4. **H12 VMEM half: the simulation side is confirmed** (old word on a
   same-port read-during-write). The XPM ``no_change`` side is unmeasured. On
   a write-write collision the sim model's DMA write wins, which is a
   block-order artefact.
5. **``tb_vpu_word_array`` does not pin the read latency.** It samples
   ``compute_rdata`` ``READ_LATENCY + 1`` edges after issue, and the pipe
   holds while ``en`` is low. Replaying its trace with ``READ_LATENCY`` set to
   1, 2 or 3 gives the word the tb checks; 4 does not. So the plan's "run at
   both values" passes trivially at 3. This trace harness's step probe is what
   pins 3 and 2. The tb also shows the DMA side reading word 512 **once** for
   its four beat reads (``vpu_dma_group`` keeps it), so it has 5 defined read
   slots in 81 cycles.
6. **``vpu.sv:291`` folds ``reduce_fire | lane_reduce_fire`` into one bit** of
   the 6-bit ``wb_source_valid``. ``vpu.sv:370``'s ``$onehot0`` cannot see a
   ``vreduce`` (13) and a ``vlanered`` (9) issued 4 cycles apart landing
   together. ``sequencer.sv:415``'s reservation check and asm's calendar still
   cover it. ``asm.py:977``'s message says "six writeback sources", but
   ``wb_addr`` ORs seven.
7. **Doc and code drift in MiniTPU** (cited lines are off by 1 to 4):
   ``UNITS.md:132-134``, ``:435``, ``:439`` and ``:154-158`` against
   ``vpu.sv``/``vpu_regfile.sv``. ``UNITS.md:770`` names
   ``mxu_input_ctrl.sv``, which does not exist. ``asm.py:978``,
   ``ISA_AND_INTERFACES.md:33`` and ``test_asm.py:180`` still describe
   multi-beat pops, but a pop is one beat at +3 (``asm.py:713``).
8. **Plan corrections.**

   * ``test_asm.py``'s refusals are ``assertRaises``, not ``pytest.raises``
     (the count of 39 is right).
   * Every refused conflict lives in ``vpu.sv``/``sequencer.sv``, as the plan
     says. At unit level only the FIFO's own assertions fire, so the tier-ii
     Allo parity check stays a composition question.
   * The plan's [I] on ``--x-initial unique`` and unpacked memories is
     confirmed.
   * The plan's "push 4 rows" in ``tb_mxu_single_port`` is **one** FIFO push
     per lane: the gather packs the 4 rows into one 64-bit entry.
