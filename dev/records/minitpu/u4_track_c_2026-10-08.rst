2. The forms
============

``dma_addr_gen`` / ``bits`` (C1)
--------------------------------

``addr(base, row, stride)``: the product formed at 46 bits, the sum
truncated to 32 on return, as the RTL's ``assign``. The DMA engine calls the
same function (``calls=("addr",)``), as ``dma.sv`` instantiates the module.

``dma_desc_adapter`` / ``bits`` (A1)
------------------------------------

The two-state FSM; ``d_i`` (57 bits) snapshotted as the four fields the
outputs read; words -> beats by shift (``{vmem_address, 2'b00}``,
``{rows, 2'b11}``). A slice store bounded by closure names warned and widened
to ``UInt(32)`` (C3); the shift is the same circuit and the warning is gone.

``dma`` / ``bits`` and ``bits_reset`` (D1 as one kernel)
---------------------------------------------------------

``dma.sv``'s one ``always_ff`` transcribed in its order with non-blocking
semantics: every register written goes to an ``n_*`` copy, reads see the old
value, the last write wins, and the copies commit at the end of the
iteration; the landing payload write (its own ``always_ff``) and the store
data capture are applied after. Reset is asynchronous (a row with ``rst_n``
low is sampled in reset). Ports: four lane arrays (``CIN``/``COUT`` scalar
columns, ``DIN``/``DOUT`` 256-bit beats as 8 x 32-bit lanes; B6/S8, U3 P-8).
Every mask and bound (``CRED_M``, ``TO_LAST``, ``PW_M1``, ...) is derived from
``DmaGeometry`` (section 3), never typed. ``bits`` declares the landing
payload ``@ Stateful(reset=False)`` (P-7, D-14); ``bits_reset`` declares it
``@ Stateful`` -- reset storage, a recorded deviation (D-13's note), invisible
on the defined slots because the RTL's payload is masked while the FIFO is
empty.

``dma`` / ``streams`` and ``streams_reset`` (D1 as the track states it)
-----------------------------------------------------------------------

``dma_unit.dma_engine`` is the same body with every port a token, between a
source and a sink over Streams, one token per link per cycle (U3 track B's
"cycle model in token time"). The interfaces it declares:

* **descriptor interface** ``x_desc`` (valid, is_store, channel, vmem_row,
  rows, cols) + ``x_base`` + ``x_stride``: ``dma_desc_adapter``'s outputs;
  ``desc_accept`` comes back in ``y_stat``.
* **credit pipe**: request ``y_req`` (valid, we, addr[29], len[8],
  rsp_ready) + ``y_wd[8]``; response ``x_rsp`` (valid, last, resp) +
  ``x_rspd[8]``; ``dm_req_ready`` in ``x_ctl``.
* **VMEM DMA port**: ``y_vreq`` (rst_n, wr_en, rd_en, wr_ptr, rd_ptr) +
  ``y_vwd[8]`` out, ``x_vrd[8]`` in -- taken by the engine *after* its
  outputs are put, which is what lets D2 close it on a VMEM unit in the same
  iteration without a cycle.

``dma_vmem`` / ``d12`` (D2): the VMEM side as a D-12 port
-----------------------------------------------------------

``vmem`` is the U2 word array at the full geometry (4,096 x 1,024 b,
``reset=False``), ports ``c`` (``rw``, latency 3) and ``d`` (``rw``, latency
``VMEM_DMA_READ_LATENCY`` = 2, P-3), ``visible=1``, ``collision=
"obligation"`` (MiniTPU #21). ``vmem_group`` owns ``vmem.d``: it is
``minitpu_core.sv``'s select (write beat outranks read) + ``vpu_dma_group``
(gather, commit on beat 3; fetch on beat 0, serve beats 1-3 from
``scatter_q``) + ``vpu_vmem_simd``'s ``dma_rvalid_q``; ``vmem_compute_idle``
owns ``vmem.c`` (one read of word 0 per cycle; U5 composes the real owner).
The engine is D1's unit unchanged; the sink is an ``Instance`` of D1's sink
bound to the group's forwarded VMEM outputs (D-17). One number,
``DmaGeometry.VMEM_DMA_READ_LATENCY``, sets the port's declared latency, the
group's rvalid depth and the engine's capture cycle; ``_p3_legality`` holds
the three equal (and refuses otherwise, naming P-3) -- in the architecture
builder, because no unit can state it (C6).

Token time adds one register that is not hardware: the generated server
puts, at iteration ``t``, the read issued at ``t - (L - 1)`` -- the word
array's ``rdata`` *after* edge ``t`` (U2's post-edge row) -- while the group,
like the DMA, samples *before* the edge; it holds the token one iteration
(``hold``). C8 records the convention.

3. The D-20 records (``dma_params.py``)
=======================================

``DmaGeometry`` declares ``CHANNELS``, ``OUTSTANDING``, ``LANDING_DEPTH``,
``TIMEOUT_CYCLES``, the beat as ``LANES`` x ``LANE_BITS``, ``VMEM_BEAT_BITS``,
``NUM_SUBLANES``, ``VMEM_ADDR_W``, ``DESC_WORD_ROWS_W``, ``ROW_BITS``,
``VMEM_DMA_READ_LATENCY``, ``PAGE_BYTES``, ``DRAM_BEAT_ADDR_W``, ``LEN_BITS``;
everything else is a property: ``BEAT_BITS``, ``STRB_W``, ``PAGE_WORDS``
(128), ``SUBLANE_SEL_W``, ``DESC_BEAT_ROWS_W`` (14), ``VMEM_BEAT_ADDR_W``,
``CHANNEL_SEL_BITS``, ``CRED_W``, ``OUT_PTR_W``, ``LND_PTR_W``,
``LND_CNT_W``, ``LND_ENTRY_W``, ``TO_W``, and the bookings
``ACCEPT_TO_REQUEST`` (2), ``LAST_BEAT_TO_DONE`` (2), ``STORE_BEAT_INTERVAL``
(= read latency + 2 = 4). The four Phase 0 instances are ``GEOMETRIES``.

Legality (one condition set, run when any variant is made), each naming the
parameter and the consequence: ``OUTSTANDING >= 1`` (0 credits never
issue); ``LANDING_DEPTH >= OUTSTANDING`` (``dma.sv:18``, a comment in the
RTL); ``ROW_BITS == DESC_BEAT_ROWS_W`` (a narrower counter truncates the beat
count silently; a lint rule in the RTL); ``BEAT_BITS == VMEM_BEAT_BITS`` (a
gearbox otherwise, ``dma.sv:20``); ``PAGE_WORDS`` a power of two and ``<=
2**LEN_BITS`` (every page-bounded burst a legal length);
``VMEM_DMA_READ_LATENCY >= 1`` (``I_ST_RDW`` counts to L-1); ``LANE_BITS <=
32`` (a tool constraint, S8, stated as one). Six wrong declarations are
refused, each naming its parameter (``dma_params.log``). Derived against
Phase 0's measurement by the cycle model on all four instances:
**STORE_BEAT_INTERVAL 4 = measured [4]**, **ACCEPT_TO_REQUEST 2 = measured
2** (a store's first request: + 1 + the read latency).

4. Hypotheses
=============

* **H9** (D1 matches ``ref_ctrl_dma`` per cycle, four instances; the landing
  payload ``reset=False``): **holds on the simulator** for both forms
  (one kernel and Streams) on all four instances, the OUTSTANDING 1/2/4 sweep
  and ``tb_dma_bandwidth``'s seed included. **SystemC refuses the declared
  form** (C2): unreset storage is lowered only for an all-``Wire`` kernel.
  With the payload declared reset (``*_reset``) csim matches everywhere. The
  Catapult column (the per-cycle claim) is track D's.
* **H10** (D2 meets the DMA contract, latencies reported, not equal to D1's):
  split in two, because the track's D2 (the VMEM DMA port as a D-12
  declaration) is cycle-locked and the plan's D2 (Streams + drain unit) is
  self-timed. **Cycle-locked D2: holds, and better than the hypothesis** --
  per cycle against a new closed-loop RTL oracle, so its latencies ARE D1's.
  **Self-timed probe** (the plan's D2): **holds on the contract**, 18/18
  (section 6), latencies not reported (untimed columns), and it exposes
  three ways the self-timed form departs from the RTL by construction (C9,
  C10, C11).
* **H1** (the C1 function matches first time): **holds** (``addr`` on both
  columns, 200,700 vectors).
* **H8** (D-20 for the DMA): **holds**: ``DmaGeometry`` with seven legality
  relations, six wrong declarations refused, two derived timings equal to
  Phase 0's.

     - SystemC emitter

       SC_THREAD's ~64 KB coroutine stack. ``compose``'s Stream-link lowering
       of an unreset D-12 memory emits its storage as exactly such a local, so
       VMEM (4,096 x 128 B) segfaults csim ("Simulation failed"). The emitter
       already moves ``@ Stateful`` and constant arrays to members for this
       reason (``EmitSystemC.cpp`` "Not locals in run()"). Repro
       ``tests/limits/new_systemc_local_array_stack.py`` (4 KB fine, 1 MB
       segfaults; the simulator runs both). Workaround: ``d12_reset_r256``
       (256 rows; every D2 trace stays below word 256, asserted).
     - Emit a local array above a size bound as a member with no reset
       action (its initial value is undefined either way).
   * - C8
     - ``compose`` server (D-12), token time
     - **semantic mismatch** (convention)
     - The server's read token ``t`` is ``rdata`` after edge ``t`` (U2's
       post row); a unit that samples its inputs before the edge (the DMA,
       ``rtl.py``'s pre convention) needs the token of ``t - 1``: a ``hold``
       register in the owner that is not hardware. Exact, but every
       pre-sampling owner must know it.
     - Say it in the D-12 docs; optionally a ``Port(sample="pre")`` that
       makes the server deliver the pipe's last stage before its shift.
   * - C9
     - Stream (self-timed form)
     - **semantic mismatch**
     - The credit is the order Stream's capacity, but a Stream has no peek:
       the response side must *take* the order token at a burst's first beat
       (it needs the destination for every beat), which frees the credit
       ``len`` beats early -- in flight is bounded by OUTSTANDING + 1 at the
       acceptor (plus any FIFO slack a backend adds), not by OUTSTANDING as
       in ``dma.sv``, which returns the credit on ``dm_rsp_last``.
     - A peekable Stream (``front()``), the same gap as U2's ``vpu_fifo``
       head register.
   * - C10
     - ``compose`` server (D-12), self-timed
     - **semantic mismatch** (found by a deadlock)
     - The server returns the read of access ``t`` only in exchange for
       access ``t + L - 1``: the read pipe advances when the owner accesses.
       The self-timed owner's last store beat was therefore withheld until
       its next access, which blocked on the next (load) descriptor's landing
       beat, which the issue unit -- waiting for that store beat -- had not
       requested: store-then-load deadlocked (bisected, seed 0, descriptor
       4). Cycle-locked owners access every cycle and never see it.
       Workaround: one flush access after every store descriptor.
     - Either document "an owner must keep accessing until its reads drain"
       as part of D-12's server lowering, or give the server a free-running
       pipe (its own iteration per cycle, independent of the owner's).
   * - C11
     - D-12 + blocking Streams (self-timed)
     - **missing abstraction**
     - ``dma.sv`` shares the one VMEM DMA port between load drains and store
       reads, arbitrated per cycle (the drain outranks). A self-timed owner
       with two blocking request Streams cannot arbitrate without a
       non-blocking ``try_get`` (B7, S9, items 18/D: not reliable across
       backends); the probe serves descriptors one after another at the port
       (no load-drain/store-read overlap).
     - A reliable ``try_get`` (or a two-input select primitive) on every
       backend; until then the arbitration stays cycle-locked (D2).

MiniTPU (FYI, P-10, not filed): nothing new. D2 re-measured Phase 0's F3
contract per cycle in the RTL: the fetch-on-beat-0 / scatter-register read
and the commit-on-beat-3 gather, both with unreset payload registers, so a
store of a word a partial load left half-gathered reads undefined beats (the
``vmem uninit`` masks).

6. The self-timed probe (H10)
=============================

``dma_selftimed.py``: ``feed -> issue -> bridge -> land -> vowner`` over
blocking Streams, with the credit as the order Stream's depth
(``OUTSTANDING``), the landing FIFO as ``s_lnd``'s depth (``LANDING_DEPTH``;
its back-pressure is ``dm_rsp_ready``), the device memory as a boundary array
behind ``bridge`` (the D-21 shim's role), and ``vowner`` owning ``vmem.d``
(``rw``, latency 2) one port access per iteration. Judged on the contract:
the request stream ``(we, addr, len)`` equal to ``dma.sv``'s on the same
descriptors (run on the RTL with Phase 0's program generator and bridge,
single channel, waited between descriptors), the device memory after the
program equal to a sequential reference (loads then stores of the same rows:
a round trip through VMEM), and every descriptor completed (store
completions counted at ``land`` on the last burst's B beat, load completions
at ``vowner`` on the last beat drained).

**CONTRACT-MATCH on all 18 runs**: instances ``core``, ``o1``, ``o4`` x
three random programs (12 descriptors each: 58 to 201 requests, loads then
stores of the loaded rows, strides 1, 2, 3 and 7, one base 5 words below a
page) x both columns (``selftimed.log``). On every run the request stream
equals ``dma.sv``'s, request for request (the RTL took 491 to 2,066 cycles
for them; OUTSTANDING 1 is the slowest), the device memory after the program
equals the sequential reference, and every descriptor completed. Simulator
~4 s and csim ~10 s per run (build included); the probe's VMEM has 256 rows
(C7). It found C10 by deadlocking before the flush was added.

Latency is not reported: the simulator is untimed and csim here checks
values, not time (``check.py``'s ``CYCLE_SEEN``); the per-cycle cost of the
self-timed form is a Catapult question (track D). What the probe does show
is where the self-timed form departs from the RTL's contract by
construction: C9 (credits), C10 (the read pipe advances only with accesses),
C11 (no per-cycle port arbitration without ``try_get``).

8. Provisional calls (D-9)
==========================

* **D1 is both forms.** The track statement asks for "the engine with its
  credit pipe as Streams and the descriptor interface"; the plan's D1 is one
  kernel. Both landed and both are held to the same oracle; the Stream form
  is the one D2 composes. *Reason:* the one-kernel form is the transcription
  reference, the unit form the composition.
* **The payload's declared form is the default** (``bits``, ``streams``,
  ``d12``: P-7), and the reset form is a separate variant, so the matrix
  shows C2 instead of hiding it.
* **D2's oracle is a new wrapper** (``u4_dma_vmem.sv``: ``dma`` +
  ``vpu_vmem_simd`` wired as ``minitpu_core.sv`` wires them, no logic) rather
  than a contract check, so D2 is held per cycle. Its reference closes Phase
  0's ``DmaModel`` (unchanged) on a transcription of ``vpu_dma_group`` and
  the word array's DMA port, verified against the wrapper and mutation
  checked (section 1).
* **The VMEM compute port is owned by an idle unit** in D2: a D-12 port must
  have one owner, and the compute side is U5's.
* **C7's workaround is a 256-row instance**, asserted against every D2 trace,
  not a smaller VMEM in the default.
* **The self-timed probe serves descriptors in order at the VMEM port**
  (C11) and flushes after every store (C10).

10. The memory-side contract (shared with the D-21 shim)
========================================================

The boundary ``dma_unit`` keeps is ``minitpu_core.sv``'s device-memory credit
pipe, unchanged in fields, widths and order:

1. Request ``{we, addr[28:0] (DM word, 32 B), len[7:0] (words - 1, never
   across a 4 KiB page), wdata[255:0], wstrb all ones}``, valid offered
   independently of ready, taken on ``valid & ready``; a store sends
   ``len + 1`` W beats, the first carrying the burst's address and length.
2. Responses in request order: a load returns ``len + 1`` words with
   ``last`` on the final one, a store one beat after its last W beat with
   ``last``; each carries ``resp[1:0]``; ``rsp_ready`` is the landing FIFO's
   room, and is 1 with nothing outstanding (stale beats dropped).
3. At most ``OUTSTANDING`` bursts between request and their ``last``
   response (the credit), and the bridge must answer within
   ``TIMEOUT_CYCLES`` of silence or the watchdog completes every channel
   with ``dma_err`` (cause 2).

Not done
========

* Catapult + DC (track D): every landed variant; C2 means P-7's declared
  form cannot reach Catapult in token time; H11 (the ``rw`` DMA port beside
  the compute port at II=1) has its unit now (``dma_vmem``).
* RTLGen / AMC (track E).
* The self-timed form with two channels in flight, SLVERR, the watchdog and
  reset (the probe's contract omits them).
* The adapter and the DMA composed (``dma_desc_adapter`` -> ``x_desc``): the
  joint oracle is the sequencer's (track B).
