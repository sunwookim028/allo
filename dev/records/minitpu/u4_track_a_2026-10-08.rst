1. What was built
=================

Every unit file gained ``VARIANTS`` (and ``WIDTH``) that ``check.py`` runs; no
harness file changed. Wide words never cross a port: a 128-bit bundle is
``UInt(32)[4]`` lanes, a record wider than 32 bits two lanes (U3 P-8; helpers
in ``units/ctrl_lanes.py``).

* **C1** (``seq_decoder``, ``agu_resolve``, ``vpu_adapter``, ``dma_addr_gen``):
  plain Allo functions -- the callees track B's issue unit calls -- held alone
  through a one-kernel region. The decoder is **one function per slot**
  (``decode_v/m/x/d/c/l/s``, each the slot's packed record, MSB first as
  ``sequencer_pkg``), never the 233-bit struct. The VPU adapter is **D-23's
  three slot commands**, ``adapt_v`` (``vpu_ctrl_t[84:38]``), ``adapt_x``
  (memory, ``[37:18]``), ``adapt_m`` (matrix, ``[17:0]``); ``slots_gated``
  adds D-23's allowed payload gating (``gate_v/x/m``).
* **S1** ``scalar_agu.s1``: one kernel; the write pipeline is **data**,
  ``S_LAT`` entries, shifted each edge with the issuing op in entry 0 and
  entry ``S_LAT - 1`` committed -- one body for ``S_LAT`` 1 (the RTL's
  ``g_lat1``), 2 and 3 (``g_latN``); SMAC's add after the pipe register; read
  ports from committed state only (no bypass).
* **F1** ``fetch.f1``: IRAM (4,096 x 128, read register, written on every
  edge) + ``sequencer_fetch_queue`` register for register, for the ``iram``,
  ``fq`` and ``fq_a8`` instances. ``fetch.f1_d12`` (``units/fetch_d12.py``):
  the IRAM as a D-12 ``Memory(host w, fetch r latency 1, reset=False)`` with
  a loader unit and the queue unit.
* **L1** ``loop_ctrl.l1``: ``sequencer_loop_ctrl`` + ``sequencer_loop_buffer``
  register for register, widths from the D-20 record. ``loop_ctrl.l1_d12``
  (``units/loop_ctrl_d12.py``): the loop buffer as a D-12 ``Memory(cap w,
  replay r latency 0, reset=False)``, the RTL's two modules as two units
  (``capture`` owns ``cap``, ``ctrl`` owns ``replay``) whose same-cycle
  overflow/control exchange is one token each way per cycle.
* **D-20** ``template/control_geometry.py``: ``ControlGeometry`` (declared:
  ``LEVEL_SEL_W``, ``INSTR_ADDR_W``, ``LB_CAP``, ``IRAM_MEM_LATENCY``,
  ``FQ_DEPTH``, ``S_LAT`` as a booking); derived properties ``STACK_DEPTH``,
  ``SP_W``, ``LB_COUNT_W``, ``LB_IDX_W``, fetch->valid, flush->target, branch
  bubbles, refetch cost, ``loop.begin.r`` skip latency; ``control_legality``;
  ``check_against_phase0`` against Phase 0's probes **and** MiniTPU's own
  bookings read from ``asm.py``/``isa_latency.json`` (P-9: through
  ``harness/minitpu_asm``); ``refusals``.
* **H6** ``template/flush_stream.py``: the fetch queue as Streams between a
  ``fetcher`` and a ``queue`` unit (plan F2), two flush forms, judged on the
  fetch contract (section 4).

4. H6: the flushable stream (probe and D-n draft)
=================================================

``template/flush_stream.py`` splits the fetch path at its FIFO: ``fetcher``
(address counter, in-flight read, IRAM) puts each landed bundle into
``fifo: Stream[UInt(128), 4]`` with ``{epoch, addr}`` in a parallel
``ftag: Stream[UInt(13), 4]`` (one 141-bit element triggers T-1); ``queue``
holds the head and serves issue. Control crosses once per cycle each way
(``k_ctl``: occupancy, flush, target; ``k_push``), so iteration = cycle and
nothing races. A Stream cannot show a FIFO's head while empty (the RTL drives
a shifted stale entry with ``valid = 0``), so the head is compared only while
valid (T-8). Two ways to get rid of what a flush strands in ``fifo``:

* ``drain``: in the flush's edge, ``get`` and discard every stranded token (a
  bounded loop of conditional gets in ONE iteration);
* ``epoch``: drop stranded tokens as they surface, one ``get`` per cycle; the
  fetcher's room test counts them, since they still occupy ``fifo``.

   :header-rows: 1

   * - trace
     - RTL

     - 2,622 issued; flush->target {3: 153, 4: 7}

     - **differs** 24,348/24,362; **2,621** issued; {3: 152, **4: 8**}

What it shows. (1) ``drain`` is exact per iteration but only because an
iteration may make up to ``DEPTH - 1`` extra gets: a FIFO serves one per
cycle, so in hardware the flush cycle stretches -- the cost is hidden from
both untimed backends, and is exactly what D-24 (cycle-locked) forbids.
(2) ``epoch`` is cycle-honest and free while issue runs at II=1 (the stranded
tokens drain inside the 2 bubbles the branch costs anyway), and costs a
bundle when the queue was full at the flush (1 of 2,622; 8 of 160 flushes
take 4 cycles). (3) It needs the room test to count stranded tokens -- or a
``2 * DEPTH - 1`` deep FIFO -- else the producer can block in ``put`` while
the consumer waits for its ``k_push``: a deadlock by construction (D-23's
condition; reasoned, not run). (4) A 1-bit epoch is **wrong**: two flushes
before the stranded tokens drain flip it back and stale bundles issue (T-5,
``f2_epochwrap`` below); in lockstep the stale COUNT is exact and is what the
prototype uses.

**D-n draft (for the owner): a stream may be flushed by its consumer.**

* ``Stream[T, D, flush=True]`` gains ``s.flush()``, callable only by the
  channel's one consumer: at that iteration's edge every buffered token is
  discarded, and a ``put`` of the same edge is dropped (the RTL's "drop the
  landing response").
* Lowering: a FIFO with a synchronous clear (``count <= 0``), no data moved --
  zero cycles, what ``sequencer_fetch_queue.sv`` is; the simulator empties the
  buffer at the iteration boundary.
* Cycle-locked producer and consumer need nothing else. A self-timed producer
  may ``put`` before it hears of the flush, so the channel (not the bodies)
  carries an epoch of ``ceil(log2(F + 1))`` bits for ``F`` flushes in flight,
  with a declared 1-deep flush link to the producer; the composition checks
  ``F`` against that link's depth.
* A backend that cannot build the clear refuses, naming the channel (D-1);
  ``drain`` and ``epoch`` stay the recorded workarounds until it lands.
* *Reverses if* a cycle-locked composition (I1) never needs a FIFO between
  fetch and issue -- then the flush stays inside one unit, as F1 has it.

5. Findings
===========

.. list-table::
   :header-rows: 1
   :widths: 6 16 78

   * - id
     - class
     - finding
   * - T-1
     - **bug** (simulator; silent, then fatal; high)
     - A ``Stream`` whose element is wider than 128 bits corrupts the heap:
       the data arrive intact, then the process aborts ("corrupted size vs.
       prev_size", "free(): invalid pointer"), segfaults, or hangs in
       ``malloc``'s lock inside LLVM's signal handler (gdb: thread 1 in
       ``__lll_lock_wait_private`` under ``SignalHandler``). 128 bits: 0 of 13
       runs; 129-160 bits: 6 of 14. Repro ``tests/limits/
       new_sim_wide_stream_heap.py`` (``REPRODUCES: {128: 0, 141: 2}`` of 5).
       Cause not isolated: the buffer is a ``memref.alloc`` of ``D + 1`` x
       ``iN`` (``allo/backend/simulator.py`` ``_process_function_streams``);
       an ``iN > i128`` store/alloc size mismatch is the suspect. Smallest
       change: refuse an element wider than 128 bits in the simulator (D-1)
       until the lowering is fixed. Workaround (F2): split the token.
   * - T-2
     - **semantic mismatch** (D-12 lowering)
     - A ``registers`` read port of latency ``L >= 1`` on Stream links
       delivers the read issued in iteration ``t`` in iteration ``t + L - 1``
       (the server's pipe-as-data puts its last entry in the same iteration;
       the word-array record's ``issue`` shift is the same fact). So the
       IRAM's ``latency=1`` read is combinational in body terms and
       ``fetch_d12``'s queue keeps the RTL's read register itself; on the Wire
       links Catapult gets, ``memory.json`` says "registered link + L-deep
       pipe", so the same body would count that register twice. A
       cycle-locked body cannot be written once for both link kinds.
       Proposal: define a port's ``L`` as iterations in the body's terms on
       every link kind (deliver at ``t + L``), the Wire link's register being
       one of the ``L`` stages; check on Catapult (track D).
   * - T-3
     - **workaround** (front end; U3 A9 again)
     - A Python ``bool`` closed over by a kernel compiles to ``scf.if`` on an
       ``i32`` (``'scf.if' op operand #0 must be 1-bit``); ``slots`` and
       ``slots_gated`` are two functions, not one with a flag.
   * - T-4
     - **missing abstraction** (Stream)
     - No stream can be flushed (H6): section 4; D-n draft above.
   * - T-5
     - **semantic** (the epoch workaround)
     - A 1-bit epoch tag drops the wrong tokens after two flushes closer than
       the stranded tokens take to drain: on the Phase 0 program trace the
       first ``epoch`` run desynchronised and hung (killed after 10 min); a
       directed repro (``u4_track_a_2026-10-08/f2_epochwrap.py`` gap 0: full queue,
       flushes on consecutive cycles) issued 2, 3 before the target 4 with the
       tag test; with the committed count test it issues 4 first. In
       lockstep, dropping by the stale count is exact; self-timed needs the
       wider epoch of the draft.
   * - T-6
     - **semantic mismatch** (documentation)
     - README D-23 names the slot commands "V (vector), X (matrix), M
       (memory)"; in the RTL and the plan (Q1(b)) **X is the memory slot**

   * - T-8

6. Provisional calls (D-9)
==========================

* **P-A1.** The decoder's interface is seven per-slot functions plus
  ``delay``, each returning its ``sequencer_pkg`` record; the 233-bit struct
  exists only in the runner. *Reason:* U3 P-8 and the plan's C1.
* **P-A2.** The VPU adapter follows D-23 with the RTL's slot names (T-6);
  ``slots`` (ungated) is the default, ``slots_gated`` the declared deviation,
  verified on the contract.
* **P-A3.** ``vmem_store_read_hint`` is grouped with the X command (gated by
  ``vmem.valid``): Phase 0 found nothing reads it.
* **P-A4.** The F1/L1 bodies keep IRAM/loop buffer as body arrays (the
  default, cycle-locked by construction); the D-12 forms are variants beside
  them until T-2 is settled on Catapult.
* **P-A5.** F2's flush uses the stale count in lockstep, the epoch tag only
  carried (T-5).
