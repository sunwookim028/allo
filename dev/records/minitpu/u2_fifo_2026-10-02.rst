The probe question
==================

Allo's FIFO primitive is ``Stream[T, depth]``. Is MiniTPU's ``vpu_fifo``
(push / pop / full / empty / head visible without a pop / count; a reset
that clears only the pointers) expressible **as** a Stream with its ports,
or only as a ``trace``/``ported`` kernel over an explicit ring? The short
answer, with the evidence below:

* **A Stream is a link, not a unit.** Its "ports" are the valid/ready
  handshake a backend owns and schedules; ``vpu_fifo``'s ports are *data*
  (``push_i``, ``pop_i``, ``pop_data_o``, ``empty_o``, ``full_o``) driven by
  a state machine. So the unit is expressible as a Stream only *inside* one
  kernel (a self-FIFO: both ends in the same kernel) behind an adapter --
  and even then only functionally.
* With a **head-register adapter** (``stream``: ``Stream[W, d-1]`` + one
  register, because a Stream has no peek), the simulator and SystemC csim
  are **bit-exact** with the RTL on every defined slot of every trace,
  illegal ones included, once one RTL quirk is special-cased (push and pop
  together on an empty FIFO lose the word in the RTL; a Stream cannot lose
  it: M3). Capacity is exactly ``depth`` on both backends.
* Without the adapter (``stream_raw``) the head-visible slots are
  unreachable (no peek: H6 confirmed), and ``try_put`` is wrong on both
  backends in two different ways (B7, S9).
* **Catapult cannot schedule the self-FIFO at all** (SCHD-30, "even with
  unlimited resources", with or without pipelining, with or without the
  reset drain, with or without the head register: the emitter's self-FIFO
  lowering puts a Connections ``Pop``/``Push`` and its synchronous occupancy
  counter into a chained feedback path). So today the Stream primitive is
  **not a route to RTL for a FIFO unit**; the explicit ring (``wire``) is,
  and matches the RTL per cycle on all three instances at a uniform +1 edge.
* RTLGen and AMC see only the explicit ring (their frontends have no Stream
  of this kind); RTLGen makes the right thing of it (4 registers, a
  combinational read mux, II = 1), AMC's pipelined schedule is wrong (A1).

What "cycle" means in each column is as in the regfile record: the
simulator checks order only; csim checks values per iteration; Catapult RTL
is compared per clock against MiniTPU's RTL under the harness ``trace``
shape; RTLGen and AMC give per-iteration values and a cycle count.

The command trace is Phase 0's joined end to end: ``w32d4`` 80,092 cycles in
10 traces (213,166 defined slots, 27,110 masked: ``empty`` 27,105,
``pre-reset`` 3, ``uninit`` 2); ``output`` 80,240 cycles in 12 traces
(219,756 defined, 20,964 masked); ``input`` 20,092 cycles (53,862 defined,
6,414 masked); ``d16w48`` 55,028 defined. The illegal traces (overflow,
underflow, push+pop on empty, random-any) are in: the reference is exact
there too, so the flags are *defined* on every cycle after the first reset.

Findings
========

Each has a minimal repro in ``u2_fifo_2026-10-02/repros.py`` (output in
``logs/repros.txt``) unless noted. The regfile's B4, B5, S6, S7, B6 all
recur and are not re-counted.

**B7 (simulator, bug, silent).** A ``try_put`` whose result is not used is
dropped: ``junk: uint1 = s.try_put(x)`` pushes nothing, ``empty()`` stays 1
after four of them; with the result used the same code works. csim is right
in both forms. The simulator's stream lowering (``allo/backend/simulator.py``
``StreamTryPutOp``) must be reached through the result's uses; an unused
result lets a canonicalizer erase the op as pure. *Proposed fix:* mark the
try ops as having memory effects (they are side-effecting on the FIFO), or
refuse an unused ``try_put``.

**S8 (SystemC csim, bug, silent).** A 64-bit port value >= 2^63 reads back
as ``0x7fffffffffffffff`` **and so does every value after it on that port**:
the testbench parses ``input<k>.data`` with ``std::ifstream >> long long``
(``kernel.cpp``: ``_f >> _v; ch.Push((ac_int<64,false>)_v)``); overflow
stores ``LLONG_MAX`` and sets ``failbit``, which sticks. Repro: ``[1, 2^63-1,
2^63, 3] -> [1, 2^63-1, 2^63-1, 2^63-1]``. The MXU output FIFO is 64 b wide,
so every csim cell of the ``output`` instance is this finding (the flags
match, ``pop_data`` does not). *Proposed fix:* parse through ``unsigned long
long`` (and ``to_uint64()`` on the way out), together with S7's word-split
format for anything wider.

**S9 (SystemC emitter, bug, silent).** A self-FIFO's ``full()`` reads a
synchronous occupancy counter (``<stream>_cnt``, ``EmitSystemC.cpp``
``emitStreamFull``) that ``try_put`` advances **even when the put is
refused**: after the first refused push the counter is ``depth + 1`` and
``full()`` (``cnt == depth``) is never true again. Repro: six ``try_put`` into
``Stream[int32, 4]`` give ``full = [0,0,0,1,0,0]`` (simulator ``[0,0,0,1,1,1]``).
*Proposed fix:* advance the counter under the ``PushNB`` result.

**C1 (Catapult + emitter, blocked; bug by D-1).** The self-FIFO lowering
(one kernel both ends of a ``Stream``, realised as an ``AlloFifoC`` bound as a
self-loop at the top with ``_enq``/``_deq`` Connections ports and the
``_cnt`` counter) is unschedulable in Catapult inside any loop that puts and
gets conditionally: SCHD-30 "even with unlimited resources", four variants,
with and without pipelining. csim accepts the same code and is bit-exact
(``stream``). The emitter does not refuse the construct for csyn. *Proposed
fix:* either lower a self-FIFO to an in-kernel ring (the ``trace`` body:
registers + pointers, which Catapult schedules at II=1), or refuse it under
``mode="csyn"`` naming the kernel.

**M3 (semantic mismatch): the Stream cannot lose a word.** Push and pop
together on an empty FIFO: the RTL moves both pointers and loses the pushed
word (Phase 0, H12); a Stream, popped first (nothing: it is empty) and then
pushed, keeps it, on both backends. A Stream-based unit can only be
bit-exact on that illegal command by special-casing it (``stream`` does; the
slot itself is masked, but the state after it is not). The same holds for a
reset with words inside: the RTL clears pointers, a Stream must be drained,
and ``stream_raw``'s remaining misses are those two.

**A1 (AMC, bug).** The pipelined schedule (II=3) of the ``trace`` kernel is
wrong: the flags (``cnt``) are exact, ``pop_data = mem[rd]`` is not from the
first fill on (first example cycle 4 of ``fill-full-passthrough-drain``).
The unpipelined build is exact at 4 cycles/iteration; the complete partition
gives the identical wrong result. Not reduced further here (AMC's own
scripts in ``amc/``).

**H6 (missing abstraction): no peek.** ``pop_data`` is the head word,
visible on every non-empty cycle without a pop. ``Stream`` has
``get``/``try_get``/``empty``/``full`` and no ``peek``, so the port needs a
head register beside the stream (``stream``); a ``Stream[W, k]`` plus the
head holds ``k + 1`` words, so the variant uses ``k = d - 1``. A ``peek()``
(Connections' FWFT ``deq.dat`` is exactly that) would make the adapter
unnecessary.

**H7 (semantic mismatch, recorded): overflow has three behaviours.** The
RTL drops the push (``output`` ``overflow`` trace: 3 of 19 pushes); the
assembler refuses it in program order; Allo: a blocking ``put`` *stalls*
(a deadlock in a single kernel), ``try_put`` *refuses* and returns 0, and the
explicit ring (``trace``) *drops* like the RTL. Only the explicit model can
be asked to behave like the hardware.

**Minor.**

* ``write_latency_manifest(project, top, declared=)`` takes a dict per
  kernel; an int raises ``TypeError``. The csyn path of ``emit_csyn.py`` does
  not write ``latency.json`` by itself (``hls.py:1514`` does it in the
  Catapult platform's own build); the manifests here were written after the
  fact and checked (``logs/latency_manifests.txt``).
* The harness ``probe_trace`` reports 2 for Catapult on both samplings
  (pre/post); the "L=1" of ``cmp_trace.py`` is MiniTPU-relative. Same fact.
* ``stream``'s ``allo==rtl`` on the masked slots is 1,608/27,110 (the head
  register holds the popped word, not the RTL's stale ``mem[rd_ptr]``): the
  masked-slot agreement is a property of the model, not of correctness.

What the owner must decide
==========================

1. **The Stream is not the FIFO unit.** Accept that MiniTPU's FIFOs are
   expressed as the explicit ring (``trace`` for verdicts, ``ported`` for
   composition, ``wire`` for Catapult) and that ``Stream`` stays the
   inter-kernel link? *[provisional: yes -- every column that reaches RTL
   needs the ring; the ``stream`` variant stays as the probe that shows the
   primitive's capacity and flags are right in simulation]*
2. **C1**: refuse the self-FIFO under csyn (D-1) now, and lower it to a ring
   later? *[refuse now]*
3. **B7, S8, S9**: fix order. *[S8 first (silent, hits every 64 b port), then
   B7 (silent), S9 with the C1 decision]*
4. **A ``peek()`` on Stream** (H6): add it (Connections has it for free;
   the simulator's ring too) so an FWFT port needs no head register?
   *[proposal only; not needed if 1 holds]*
5. **Pointer widths** (``wire_np``): once B4 is fixed, the shared body can
   use the RTL's widths and recover 18 % of Catapult's area at 32x4.
   *[follows B4]*
6. **AMC A1**: report upstream with ``amc/fifo_amc.py``; not an Allo defect.
