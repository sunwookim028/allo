README D-12 (``28645725``) said what a memory with ports is and named its
*reverses-if*: "the regfile prototype (three reader units and one writeback
unit) cannot match MiniTPU per cycle on Catapult, or a two-port VMEM cannot
reach II=1". This record is the prototype: the declaration in
``allo/compose.py``, its composition rules and their refusals, two lowerings
to SystemC/Catapult (D-13 combinational reads, D-14 unreset storage), the
simulator path, ``memory.json``, the ``vpu_regfile`` as four units and the
two-port ``vpu_word_array`` as two units, each measured on every backend
against MiniTPU's RTL, and DC in the U2 flow.

**Result. Neither reverses-if fired.** The four-unit register file is
**bit- and cycle-exact to ``vpu_regfile.sv`` on Catapult RTL: 180,780/180,780
defined slots at read latency 0, write visible 1**, under both lowerings
(``server``: one storage kernel; ``replica``: one copy per read port), with
every port kernel at **II=1, 1 c-step**; DC same flow **4,061.6 um^2**
(``server``) against MiniTPU's **4,021.7** (+39.9, **+0.99 %**) and the
one-kernel D-13/D-14 form's **4,033.9** (+27.7, +0.69 %). The two-port VMEM
(``narrow``, 8 x 64 b, ``rw`` at 3 and 2) as two units on one declared memory
**schedules at II=1** and is **cycle-exact: 67,717/67,717** on both ports
(read 3 / 2, write -> read 1 on all four port pairs). On the simulator and in
SystemC csim both units match (Stream links); the Wire form's csim is the
known limitation 22 offset (+3/+2/+2, exactly the D-13 ``comb`` form's).
Composition refuses two owners of a port, a read through a ``w`` port, a
write through an ``r`` port, two accesses per iteration on ``count=1``, an
access under control flow, a dangling port, binding the memory itself, two
write-capable ports under ``collision="refuse"`` and Vitis on more than one
owner -- each naming the port. ``allo.memory.Memory(latency=, depth=)`` is
refused (D-12's last bullet). The ``mid`` VMEM (4,096 x 64 b, a RAM) is where
the one-kernel form already stood (``u2_word_array``): Catapult's sync-RAM
model does not give a write-next-cycle-visible two-port RAM at II=1
(SCHD-30); it schedules at **II=2** on ``ccs_ram_sync_dualport``.

1. What was built
=================

``allo/compose.py`` (+~740 lines), ``allo/backend/systemc_group.py`` (new,
100 lines), ``allo/backend/hls.py`` (+9), ``mlir/lib/Translation/
EmitSystemC.cpp`` (+11), ``allo/memory.py`` (+13),
``examples/minitpu/units/vpu_regfile_d12.py`` and ``vpu_word_array_d12.py``
(new), ``tests/dataflow/test_compose_memory_ports.py`` (new, 14 tests).

**The declaration** (``compose.Port``, ``compose.Memory``)::

   VREG = Memory("vreg", "UInt(W)", rows="32",
                 ports=(Port("ra", "r", latency=0), Port("rb", "r", latency=0),
                        Port("rc", "r", latency=0), Port("w", "w", visible=1)),
                 collision="refuse", reset=False)

   @unit(memories=("vreg.ra",), reads=("ra",), writes=("qa",), parameters=("N",))
   def rd_a(mem):
       for _ in range(N):
           a5: UInt(5) = ra.get()
           a: int32 = a5
           qa.put(mem[a])

   @unit(memories=("vreg.w",), reads=("wa", "wd", "we"), parameters=("N", "W"))
   def wb(mem):
       for _ in range(N):
           ...
           if e:
               mem[x] = d

A ``Memory`` without ``rows`` is today's boundary array. With ``rows`` and
``ports`` it is on chip; a unit binds a **port** (``"vreg.ra"``), never the
memory. ``Port(name, kind, latency, visible, count)`` as D-12 words it; a
``w`` port refuses a ``latency``, an ``r``/``rw`` port requires one.
``collision`` is checked at declaration: two write-capable ports under
``refuse`` are refused ("nothing can refuse it statically"); ``obligation``
requires ``Architecture(obligations={mem: "<why>"})``.

**Composition rules** (``Architecture._check`` and ``port_uses``), each a
test in ``test_compose_memory_ports.py`` with its message:

* one owner per port (``port 'vreg.ra' is bound by both rd_a and rd_c_on_ra;
  each port has exactly one owner``), and no port without one (``port
  vreg.rd has no owner; a port nobody binds is refused, like a channel nobody
  reads``);
* a port is reached only as ``p[address]``; every access sits in the unit's
  one top-level ``for`` loop (one iteration = one cycle of the port) and not
  under control flow, except a write alone under ``if <enable>:`` (the enable
  is a pin of the port; the S6 shape);
* direction (``reads through a write-only port``, ``writes through a
  read-only port``) and ``count`` (``2 reads per iteration through a port
  that serves count=1``); an ``rw`` access has one address;
* binding the memory itself (``binds memory 'vreg' itself; a memory with
  ports is reached through a port: bind one of vreg.ra, ...``);
* Vitis: ``NotImplementedError`` on any ported memory with more than one
  owner (owner's decision in D-12), at ``plan()``/``region("vhls")``.

**Lowerings** (``Architecture.plan``; ``region(target, lowering={mem:
...})``). ``local``: one unit owns every port -- the degenerate case, today's
kernel-local array. ``server``: one generated kernel ``<mem>_mem`` holds the
storage; each port is a bundle of links to its owner -- address (``comb``),
data and enable (``comb``), read data (``comb`` at latency 0, a registered
``Wire`` plus a pipe-as-data of ``L`` for ``L >= 1``). ``replica``: every
``r`` port's owner holds a copy, the one ``w`` port's owner sends each write
(address, data, enable) to every copy; refused for ``rw`` or two write ports
("N_R x N_W copies and a live-value table"). ``shared``: one region-scope
``Stateful`` the owners address -- kept only to record that D-11 refuses it
on every backend (``logs/a0_shared.txt``). ``target="simulator"`` emits every
link as a Stream (the simulator refuses ``Wire``); the SystemC target emits
the declared ``Wire``/``comb`` links. The composed sources are in
``composed/`` (``server``: 112 lines for the regfile; the generated server
is the last kernel). Only ``visible=1`` has a lowering (a write at an edge,
seen next cycle); any other value is refused by ``plan``.

**Storage** follows D-14: ``reset=False`` (MiniTPU's) becomes ``@
Stateful(reset=False)`` on the server's (or each copy's) array -- an
``sc_signal`` array written from a clock-edge ``SC_METHOD`` with no reset
action. With ``reset=True`` and an ``rw`` port at ``L >= 1`` the server
writes each port as ONE ``if en: write else: read`` (the RAM-mappable form
``u2_word_array`` found; a read in a write cycle is undefined, as MiniTPU
masks it).

**Catapult as one unit** (``configs={"synth_group": {"name", "kernels"}}``,
``allo/backend/systemc_group.py``). The hardware to measure is the union of
the port owners and the server, not one kernel; ``synth_top`` names one
module. ``add_synth_group`` adds an ``SC_MODULE`` to the emitted file holding
those instances and the signals between them; every signal that also reaches
a kernel outside becomes a port of it. Only ``sc_signal`` links may cross the
boundary (a Connections channel crossing is refused, naming the signal). The
region's own ``top`` is untouched, so csim runs as before; ``run.tcl`` names
the group. ``Architecture.port_kernels()`` lists the members.

**memory.json** (``Architecture.memory_manifest``; ``build(project=)``
writes it beside ``latency.json``): per memory the lowering, the
implementation sentence, the storage, the obligation if any, and per port
its kind, owner, latency/visible and how the read and the write are realised
(``catapult/cat_server/memory.json``). ``status`` is ``untimed`` on the
simulator, ``lowered`` elsewhere.

**Two fixes on the way.** (a) ``EmitSystemC.cpp``: the testbench's
``__allo_state_save`` calls are now under ``#ifndef __SYNTHESIS__`` like the
method itself; without it every design with a ``@ Stateful`` failed ``go
analyze`` (CRD-135 "has no member __allo_state_save") -- the one-kernel
``comb_unreset`` never saw it because its state lived in a kernel the TB did
not save. (b) ``allo.memory.Memory(latency=, depth=)`` raises
``NotImplementedError`` naming D-12 (``tests/test_memory.py`` updated:
``test_memory_all_options`` now asserts the refusal).

4. The owner's alternatives
===========================

The reverses-if did not fire, so the alternatives were built as lowerings
rather than as fall-backs:

* **write-broadcast replica** -- ``lowering={"vreg": "replica"}``, measured
  above (match; 2.2x the Catapult area score of the server);
* **one register array with N combinational read processes** -- this is the
  ``server`` lowering as Catapult realises it: ``vreg_mem_0`` holds one
  unreset array, its three latency-0 reads are ``comb`` pins (``'ports':
  {'v82': 'comb', 'v84': 'comb', 'v86': 'comb'}`` in ``latency.json``), the
  write is the D-14 clock-edge method;
* **Catapult RAM library** -- exercised on the ``mid`` VMEM
  (``ccs_ram_sync_1R1W`` by default, ``ccs_ram_sync_dualport`` by
  hand-patch): II=2, as above. The regfile has no reason to leave registers.

6. What this record did not do, and what is open
=================================================

* ``visible`` other than 1, ``count > 1`` on hardware, a ``w`` port with
  ``count > 1`` (the OR-mux write port as several pins) -- declarable,
  refused or untested; ``plan`` refuses what has no lowering.
* The Actions-layer port calendar (D-12's fourth bullet) is phase two; nothing
  here touches ``allo/actions.py``.
* The ``mid`` VMEM at II=1 needs a RAM model with write-next-cycle
  visibility; Catapult's library does not give one (same as U2). RTLGen/AMC
  (M2) are the places to ask.
* The word array's Wire-form csim offset is unmeasured; the harness probe's
  held-address fix is proposed, not applied.
* Vitis refuses every ported memory with more than one owner (owner's
  decision); ``memory.json`` for Vitis is therefore only the refusal.
* The DC comparison of lowerings is blind to replicas (register merging);
  use Catapult's area score or disable merging for that question.
