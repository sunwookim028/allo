  ``ninja`` itself; it re-ran 77 steps (44 compiles, relinks) while the
  branch pytest was running in that worktree. Cause: ninja's tblgen mtime
  non-convergence on a fresh build (``AlloEnums.h.inc`` newer than objects
  compiled from it in the same pass) -- the baseline tree shows the same 77
  steps under ``ninja -n -d explain``. Same sources, compiler and flags, so
  the relinked modules are equivalent; the pytest outcome diff shows no
  effect. Next sync: run ``ninja`` twice in ``build.sh`` (or run
  ``reproduce.sh`` before the pytest) so the tree is converged first.

  build); ``gates.sh`` runs ``systemc_csim`` and eva under ``env-zhang21.sh``

  path as well where ``template/calendar.py`` is gone; ``pytest.sh`` is sync
  5's run-2 form on both sides; ``ipint.sh`` is the dedicated

  core_fixes_4 / U4 verdicts on both backends.
* Load: ``ninja -j16`` twice (one build per side, sequential), pytest serial,
