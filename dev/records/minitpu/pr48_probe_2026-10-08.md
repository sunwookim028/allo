## 4. MiniTPU `mxu.sv` as an RTLModule: feasible through a shim, DIM=2 shown

MiniTPU read-only at `scratch/../minitpu` `b3ba0a4d`. Sources needed (the
unit suite's list): `vpu_pkg, vpu_fifo, mxu_acc24_add_pipe, vpu_bf16_add,
mxu_bf16_mul_acc24, mxu_pe, mxu_systolic_array, mxu`. All built clean under
the PR's `--cc --build` (which passes no `-Wno-fatal`).

### What `mxu.sv` exposes vs what `Port` can describe

| `mxu.sv` pin | Kind | RTLModule descriptor |
| --- | --- | --- |
| `clk_i`, `rst_ni` | clock, active-low reset | `clock="clk_i", reset="rst_ni", reset_active_high=False` -- fits |
| `input_push_i` / `input_ready_o` / `input_data_i [DIM][16]` | push/ready stream | `Port(..., valid="input_push_i", ready="input_ready_o")` fits the handshake (`push && !full`), **but the data pin is a packed array**: `validate_rtl` rejects any non-`BASICDTYPE` pin ("Packed/unpacked aggregate pin unsupported"), and payloads are 1/8/16/32-bit integers only |
| `input_kind_i` (enum `mxu_input_kind_e`, LHS/RHS) | sideband travelling with the data | **no descriptor** (enum pin rejected; no sideband/scalar wire kind) |
| `input_accept_o` | informational pulse (`push(t-1)`) | no descriptor; must be left unbound (outputs may be) |
| `weight_commit_i` | one-cycle pulse, timed to the last weight beat's *accept* | **no descriptor** (a plain input wire; `validate_rtl` fails on any unbound input) |
| `output_pop_i` / `output_valid_o` / `output_data_o [NS][DIM][16]` | pop/valid = ready/valid | handshake fits as `Port(dir="out", valid="output_valid_o", ready="output_pop_i")`; data is a 3-D packed array of `NS*DIM*16` bits = 128 b at DIM=2, 1,024 b at DIM=16 -- **never fits a 32-bit payload** |
| `DIM`, `FIFO_DEPTH`, `OUTPUT_FIFO_DEPTH` | parameters | `parameters={"DIM": 2}` -> `-GDIM=2` works; `defines` could set `MINITPU_NUM_SUBLANES` |

Binding `mxu.sv` directly therefore fails at the first pin check
(`validate_rtl -> ValueError: Packed/unpacked aggregate pin unsupported:
input_kind_i`; `probe_raw_and_hls.py` (a)).

### The shim (`scratch/pr48_mxu/mxu_shim.sv`, 60 lines) and what it fixes

`mxu_shim #(DIM=2)` presents exactly what `Port` can bind: `in_data[31:0]
/ in_valid / in_ready` and `out_data[31:0] / out_valid / out_ready`, and
derives every sideband from word counts, so **one RTLModule call = one tile
op**: `DIM` RHS words (vmatload, rows in reverse so the first beat ends in
the bottom row), `weight_commit_i` pulsed on the cycle the `DIM`-th weight
beat is *consumed* (`input_accept_o`; the same cycle as a push would
toggle the bank before the beat lands), `NS=4` LHS words (one vmatpush),
and the output group handed back as `NS` 32-bit words (one row of `DIM`
lanes each) with `output_pop_i` on the last word (vmatpop). Counters wrap
at `DIM+NS` / `NS`, so consecutive calls stay aligned and the two weight
banks alternate as in the core.

Descriptor:

```python
ip = RTLModule(top="mxu_shim", rtl=[...8 MiniTPU files..., "mxu_shim.sv"],
    ports=[Port("x", "in_data", "in_valid", "in_ready", size=DIM + NS, ctype="uint32_t"),
           Port("y", "out_data", "out_valid", "out_ready", dir="out", size=NS, ctype="uint32_t")],
    clock="clk_i", reset="rst_ni", reset_active_high=False,
    start=None, done=None, persistent=True, parameters={"DIM": 2})
```

Region: `feed` (puts `T*(DIM+NS)` words) -> `compute` (`for t in range(T):
ip(a, c)`) -> `drain` (gets `T*NS` words), `Stream[uint32, 4]` links,
`df.build(target="simulator")`.

**Result** (`run_mxu_shim.py`, with the JSON `validate_rtl`): `validate_rtl`
lists the 8 pins; **T=3 and T=5 tiles of random bf16 weights/activations:
12 and 20 output words bit-identical to `ref_mxu.mxu_row`** (the acc24
chain + `pack_bf16`, from `origin/u1-pilot`'s
`examples/minitpu/harness/ref_mxu.py`) through Verilator inside the
3-kernel region, with persistent state and bank alternation across calls.
The first run needed `validate_rtl` bypassed (`--novalidate`); the
`--cc --build` and transactor compile then worked unchanged.

### What the adapter cannot express (the gaps)

1. **Aggregate/enum pins and payloads > 32 bits.** Everything wider must be
   serialised in the shim: at DIM=4 one row is 64 b (2 beats in, 8 beats
   per group out), at DIM=16 256 b in / 1,024 b out (8 and 32 beats). The
   shim as written guards `DIM*16 == 32`; DIM=4 needs a 2-beat
   deserialiser/serialiser (not written).
2. **Sideband wires and pulses** (`input_kind_i`, `weight_commit_i`,
   `input_accept_o`): no `Port` kind for a scalar wire; a shim must encode
   them in the word order (count-based protocol) or in payload bits.
3. **Fixed transfer counts per object, and one instance per object.**
   Termination without `done` is "every output port reached `size`"; a
   zero-output call (a load-only `vmatload`, or a `vmatpush` whose result
   is popped later) finishes before its inputs are consumed, and
   `_validate_description` demands a positive size or a `done` pin for
   every output. The persistent Verilator model is `static thread_local`
   **per generated function**, i.e. per RTLModule object, and the builder
   enforces one static call site per object -- so three objects
   (load/push/pop) would be three separate MXUs, not three instructions on
   one. Instruction-level granularity (vmatload / vmatpush / vmatpop as
   separate program steps on one MXU, the thing TinyTPU-isa and
   `examples/minitpu`'s lockstep composite do) is **not expressible**; the
   call unit must be a whole tile op, or a shim with a `done` pin plus a
   command-word protocol, still with one fixed output count per object.
4. **No overlap.** `ii=0` only: a call blocks its kernel until the outputs
   drain. The MXU's double-banked weights (loading tile k+1 while tile k
   streams) cannot be exercised through the adapter.
5. **Vitis side.** `target="vitis_hls"` needs `hls=HLSBlackBox(c_model=...)`
   ("RTL synthesis requires an HLSBlackBox describing a supplied wrapper";
   probe (b)): a C++ model of the tile op (a port of `ref_mxu.mxu_row`:
   bf16 x bf16 -> acc24 chain -> `pack_bf16`) for csim/cosim, and either
   a supplied `ap_ctrl_chain` wrapper (`ap_ce/ap_start/ap_done/ap_continue`
   + `ap_fifo` pins) or `ReadyValidAdapter(clock_enable=...)`, which
   requires an **active-high clock-enable on the core** -- `mxu.sv` has
   none, and the generated `mxu_shim_allo` wrapper fails elaboration
   against the ce-less shim (`RTL pin ce: expected ('input', 1), found
   None`; probe (c)). A ce would have to gate every `always_ff` in the shim
   and the core (or be a supplied wrapper that stalls by withholding
   pushes). Also: every project with an RTLModule gets
   `config_compile -pipeline_loops 0`, Vitis 2023.2 only, `hw`/emulation
   rejected.
6. **Verilator flags are fixed.** No way to pass `-Wno-fatal`, `--assert`,
   `--timing`, `--build-jobs`; MiniTPU's own suite uses `-Wno-fatal
   --timing`. `mxu` happened to build clean; without `--assert` the
   `ifndef SYNTHESIS` switch-rule check in `mxu.sv:259` is silent.
7. **Verilator 5.052 incompatibility** (`--xml-only`), above; fixed by the
   JSON port.
8. **Simulation semantics.** The transactor is untimed with respect to the
   rest of the region (one `VerilatedContext` per call-site thread, 8 reset
   cycles once, `MAX_STALL=500000` no-progress cycles then `abort()`), so
   it is a functional check, not the cycle model `check.py` holds the U3
   composites to. `mxu.sv` never checks output-FIFO full (`mxu.sv:44`);
   the per-call pop keeps it bounded here.

### What `examples/minitpu-rtl/` would need

* `mxu_shim.sv` generalised: `DIM*16/32` beats per input row and
  `NS*DIM*16/32` per output group (DIM=4: 2 / 8; DIM=16: 8 / 32), the same
  count-based kind/commit/pop; optionally a `ce` if the Vitis adapter path
  is wanted.
* `ref_mxu`-based expected values (as in `run_mxu_shim.py`) and, for Vitis,
  a C++ tile-op model.
* The JSON `validate_rtl` port (or a Verilator with `--xml-only`), and a
  `-Wno-fatal`/`--assert` pass-through if the core is to be built with
  MiniTPU's flags.
* Accept the granularity: a region whose `compute` kernel calls the tile op
  `T` times, not an instruction stream. As a *baseline* for "MXU RTL inside
  an Allo region, outputs checked against `ref_mxu`" it works today with the
  shim; as a stand-in for the ISA-level composite it does not.
