2. Hypotheses
=============

* **H1** (S1 matches first time): **yes for the arithmetic** -- no vector
  ever differed on either backend; the three builds before the first run were
  tool findings (A1-A4), none in the logic. The ``sfu.sv`` transcription in
  ``int32`` with masks reused nothing of U1 and needed no B1/B4 workaround.
* **H3** (T1 matches; Catapult's free depth): Sim and SC **yes** at both
  geometries; the depth is track C's. T1 carries the declared depths as
  pipe-as-data (``declared(inst)``: ``1 + 2*LEVELS``), so ``latency=13`` is a
  one-line pin when C needs it.
* **H5** (derived legality refuses a wrong adder latency): **yes**.
  ``tree_legality`` holds ``MAX_LATENCY``, ``ROOT_LATENCY``, ``TAP_LATENCY``,
  ``TAP_LEVEL``, ``TAP_BASE``, ``LEVELS`` and ``N`` to ``LANES``, ``SUB`` and
  ``ADD_LATENCY``; every wrong set is refused with the derivation in the
  message, including ``ROOT_LATENCY=13`` at 16 leaves (the shipped constant
  at the wrong geometry) and ``ADD_LATENCY=3`` with the rest not re-derived.
  **Gap behind it** (missing abstraction, A7): a ``compose.Unit`` has no
  latency of its own, so the adder's 2 is a *parameter* (``ADD_LATENCY``)
  the composition trusts; D-10's ``latency.json`` exists only after a backend
  runs. The sink's pipe depths are the one place the derived numbers are
  consumed here; on cycle-locked RTL they are what ``latency=`` would pin.
* **H12** (wide ports: B6/S7/S8 recur unless ports are lane arrays): **not
  tested as stated** -- every variant used lane arrays from the start (P-8:
  ``uint16[n, 64]`` for the 1,024-bit tile and tree words), and no S7/S8
  recurred. What did recur in the lane-array form is **new**: A5 (a 2-D
  output's last-iteration stores dropped by csim), silent and deterministic.

3. Findings
===========

Classified per D-9. ``repro_*.py`` in the record directory; each runs alone
(``$ALLO_PYTHON repro_x.py <project dir>``).

**A1 -- workaround (known, C4 class).** A module-level numpy array cannot be
indexed in a kernel (``Unsupported global variable``); it is bound to a
kernel-local constant (``rom: int32[2048] = ROM``), which lowers to a
``memref.global`` + ``get_global``. ``sfu.py`` does this for the two
2,048-entry ROMs and the two 32-entry PWL tables (the data read from the
clone's ``.mem`` files, the same reader as ``ref``). H2's question (what each
backend makes of a 2,048 x 16 b constant) is open for tracks C and D.

**A3 -- bug (core, silent-then-loud).** ``allo/passes.py:471``
``decompose_library_function`` erases every module-level op whose
``sym_name`` starts with ``gelu``, ``layernorm`` or ``tril`` -- the library
functions it means to replace -- so a user constant named ``gelu_rom`` (or a
user function ``gelu_addr``) is deleted and the simulator's pass pipeline
fails with ``'memref.get_global' op 'gelu_rom' does not reference a valid
global memref``. ``repro_gelu_name.py``: ``tab_gelu`` ok, ``gelu_tab``
fails. Workaround: no symbol starting with those three prefixes (``sfu.py``
names them ``rom_gelu``). Proposal: match the library functions by the exact
names ``decompose_library_function`` generates, and only ``func.func`` ops.

**A2 -- bug (SystemC emitter).** A constant global referenced from a *helper*
function (a callee, not a ``df.kernel``) is not declared in the emitted C++:
``kernel.cpp: 'rom' was not declared in this scope``. ``EmitSystemC.cpp``
emits constant globals only inside ``emitKernelModule`` (as ``static const``
locals before the kernel body, ~l.3058) while helpers go through
``VhlsModuleEmitter::emitFunction`` (~l.5156) with no global emission.
``repro_global.py`` ("df helper/systemc csim"). Proposal: emit each constant
global once at file scope before the helpers and drop the per-kernel copies.

**A4 -- bug (SystemC emitter, follows A2).** Passing the constant array down
to the helper instead (``sfu_bits(op, x, rom: int32[2048], ...)``) emits the
caller's array ``const int32_t[]`` and the callee's parameter ``int32_t*``:
``invalid conversion from 'const int32_t*' to 'int32_t*'``. Workaround (the
shipped S1): the table *lookups* stay in the kernel and the helper takes the
four words; two small address helpers (``gelu_addr``, ``exp_addr``) keep the
transcription readable. Proposal: emit memref parameters a callee never
stores to as ``const T*``.

**A5 -- bug (SystemC csim, silent, high).** When a kernel's last iteration
ends with several stores to a 2-D output array, only the first of them is
kept: ``xlu_reduction_tree`` T1 and T2 at n16 read back
``lane_result_o[last] = 0x....50e2`` with lanes 1-3 zero (204,119/204,120,
the single differing slot, deterministic across runs), while n64 passed
because the data happened to leave the top lanes equal. ``repro_lastrow_multi.py``:
with ``a[t], b[t], c[t]`` stored before ``d[t, 0..3]`` the last row of ``d``
comes back ``[152, 0, 0, 0]``; with ``d`` stored first every row is right.
The plain 2-D case (``repro_2d_lastrow.py``, one output) does **not**
reproduce, so it is the interaction of the kernel's end with pending memory
writes to the last-written array. Workaround (both tree variants): store the
lane array first. Proposal: have the testbench drain every output memory's
pending writes before sampling (or the kernel's ``done`` wait for them).

**A6 -- missing abstraction / refusal (SystemC emitter, D-14).** ``tile @
Stateful(reset=False)`` in a kernel with array (memory) ports is refused:
"the kernel has a non-Wire argument (argument 0); the write runs at every
clock edge, which matches the kernel's iterations only when every port is a
Wire". The refusal is correct under D-14's lowering, so X1's SC verdict uses
the reset tile (a recorded deviation, as D-13 already allows for storage).
The honest unreset form is U2's ``comb_unreset`` shape (a ``src`` kernel over
Wires, the tile kernel Wire-only, a ``sink``), not built here for time;
it is the natural X1 on Catapult and belongs to track C with A2-style ports.

**A7 -- missing abstraction (compose).** A ``compose.Unit`` cannot declare a
latency, so a derived-latency legality has to take the adder's latency as an
architecture parameter (``ADD_LATENCY``), which nothing checks against the
unit. The ``ip_gaps`` pattern (legality on parameters) works for geometry;
for timing it wants a unit-level ``latency`` that the legality can read and
``latency.json`` can be checked against (D-10).

**A8 -- harness note (minor).** ``check.py`` hands a trace runner ``(mod, cmd,
n, w)`` without the instance, so a geometry-bearing unit's runner cannot know
``N``; ``xlu_reduction_tree`` keeps the last built instance in a module
variable (``_BUILT``). Track B's ``mxu`` (DIM 2/4/16) has the same need; the
fix is ``check_trace`` passing ``inst`` when the runner's signature takes it,
as it already does for ``make`` -- left to the integrator (shared file).

**A9 -- front-end note.** A Python ``bool`` closed over by a kernel
(``if unreset: tile ... @ Stateful(reset=False) else: ...``) is compiled as
an ``scf.if`` on an ``i32``, not folded: ``'scf.if' op operand #0 must be
1-bit signless integer``. Variants that differ by a declaration are two
functions (``xlu_transpose.trace`` / ``trace_unreset``).

**A10 -- compose note.** Unit bodies annotate their parameters with
architecture names (``op: UInt(8)[NCYC]``), so the module needs ``from
__future__ import annotations`` (as ``examples/tinytpu/ip/reduce.py`` has)
or the decorator fails at import with ``NameError: NCYC``.

4. Proposals for the core (no patches here)
===========================================

1. ``allo/passes.py`` ``decompose_library_function``: exact-name match on
   ``func.func`` ops only (A3). One-line; a regression test is
   ``repro_gelu_name.py``.
2. ``mlir/lib/Translation/EmitSystemC.cpp``: constant globals emitted once at
   file scope before helper functions (A2); ``const`` memref parameters for
   read-only callee arrays (A4).
3. SystemC csim testbench: drain pending output-memory writes before the
   kernel's ``done`` is honoured (A5). Regression: ``repro_lastrow_multi.py``.
4. ``compose.Unit.latency`` (A7) -- a D-10 follow-up, for the owner.

5. Provisional calls made (D-9)
===============================

* **P-A1.** S1 keeps "one function of ``(op, operand)``" with the table reads
  in the kernel (A2/A4 workaround) rather than inlining the whole body (which
  S2 does anyway). *Reason:* the helper is what a ``sfu_group`` of 16 lanes
  would instantiate; the workaround moves four reads, not the logic.
* **P-A2.** X1's SC verdict is taken with the tile **reset** and the unreset
  form recorded as refused, not blocked. *Reason:* the refusal is D-14 working
  as written; the Wire-only unreset form exists (U2) and is track C's shape.
* **P-A3.** T2's wavefront word is ``UInt(17)`` = ``{op, value}`` on every
  stream, so the op travels with its data (as the RTL's ``op_q`` pipe does),
  and the valid/reset pipes live in the sink at the derived depths. *Reason:*
  a self-timed tree has no cycle to attach a valid to; the sink is where the
  RTL's contract (valid 13 edges later, cleared by reset) is restated.
* **P-A4.** The tree's node numbering is the heap form of
  ``ip/units/reduction_tree.py`` (``node[N + m]`` has children ``2m``,
  ``2m + 1``), in three instance groups (below / at / above the tap) of one
  body, so no instance puts conditionally. *Reason:* one writer per stream
  element is a structural fact, not a runtime branch (``stream_ports.rst``).
* **P-A5.** No second geometry for the transpose (16 x 4 only), per the plan.
