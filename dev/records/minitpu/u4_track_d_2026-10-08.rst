1. Method
=========

**The check is ``check.py``'s, with the Catapult RTL as the backend**
(``scripts/u4d_check.py``). ``check.py`` has no Catapult backend; U3 track C
wrote a comparator per port order. Here the unit's own runner
(``VARIANTS[v][1]``, or a form's ``run``) is called with ``CatapultRtl``
standing in for the built module: called with the region's arrays in
declaration order, it drives ``concat_sim_rtl.v`` in Verilator -- every input
port offers row ``t`` until accepted, every output always ready -- and writes
each output port's tokens back into the caller's arrays. The trace set
(``check._trace_all``), the RTL oracle run, ``u.REF``'s masks and the
comparison over every defined slot are ``check.check_trace``'s, unchanged;
only the backend differs. A ``comb`` unit (``dma_addr_gen``) takes
``check.main``'s stimulus path.

**``cycle=per-cycle``.** Every accepted row and every output token is
stamped with its clock cycle. A verdict line gives the rate (row accepts per
cycle), the stall cycles (rows not accepted one cycle after the previous), the
measured ``L`` per output (token edge minus its row's accept edge, ``rtl.py``'s
count), and the **row -> token offset**: output token ``t`` leaves at cycle
``t + c``. **CYCLE-FOR-CYCLE yes** = one ``c`` over the whole trace and 0
stalls: with the values equal to the oracle's row ``t``, the Catapult RTL is
MiniTPU's timing shifted by ``c`` edges (U3's "cycle-equal", generalised to a
composite whose ``c`` is not 1 + the first accept). The manifest is held to
the measurement (``latency.verdict`` for one kernel, ``latency.composite``
for several).

**Schedule.** Every kernel's iteration loop pipelined at II=1
(``--pipeline-all``); every nested constant-trip loop marked fully unrolled
(``--unroll-nested``, D-2 below); ``latency=1`` pinned on every one-kernel
unit (the RTL's register edges are rows of data, so the Pop->Push edge
completes them: U3 track C section 2); composites free.

**Forms.** Only ``seq_issue``, ``vpu_cmd``, ``vpu_wb`` and ``dma_addr_gen``
reached a per-cycle Connections boundary as landed. Every other unit has a
``[n, k]`` lane array (P-8) or a conditional port read, which the emitter
makes RAM pins (U3 track C's C1 and C2, again). ``forms/`` holds one
track-D form per unit, changing only the boundary: one ``UInt(32 k)`` port
per row, every port read once and unconditionally at the top of the
iteration; the body's logic is the landed text (``dma`` and the DMA
composites are generated from it, ``scripts/gen_dma_bits_form.py``). The
runner is the unit's own: ``CatapultRtl`` packs a ``[n, k]`` lane array into
the one wide port (lane 0 the LSBs) and unpacks outputs.

**DC.** Each Catapult ``concat_rtl.v`` through ``dc_u3c.tcl`` at the build's
clock; MiniTPU's own module (its ``u4_*`` wrapper, which has no logic, or the
module itself) through the same flow at both clocks (``dc_minitpu.txt``;
comb modules on a virtual clock). The sequencer is synthesised with
``sequencer_iram`` cut to 2 rows (``scripts/gen_iram_dc.py``: FreePDK45 has
no memory macro, asic_memories s.1.1). Registers are counted in the mapped
netlist (``ungroup -start_level 2`` keeps a level of hierarchy that the top's
reference report hides). Fmax = 1 / (period - worst slack); DC stops
optimising at slack 0, so 300/500 MHz rows are "met", not a limit.

4. T-2 on Catapult RTL, and the D-12 amendment
==============================================

README D-12's 2026-10-08 amendment: "a port's latency is counted in the
owner's own iterations on every link kind" (deliver at ``t + L``). T-2: on
Stream links a ``registers`` port of latency ``L`` delivers at ``t + L - 1``,
so ``fetch_d12``'s queue body keeps the RTL's read register itself.

**What had to change to build ``f1_d12`` for Catapult at all.** On the
SystemC target the server's pins are ``comb`` (address, data, enable) and the
read data a registered ``Wire``. The landed composition (Stream channels from
``src`` to the owners) is **refused at emit** by D-13's rules, verbatim:
``comb port `iram_host_a` (loader_0): its value reads a stream or channel; a
combinational output may read only Wire inputs and storage`` and ``comb port
`iram_fetch_a` (fq_0): its value reads next_addr after a store to it in the
same iteration``. ``forms/fetch_d12_packed.py`` therefore (a) links ``src`` ->
owners -> ``sink`` by ``Wire`` channels, (b) writes the queue body "every
state read first, then stores" (the address as a select of the old state;
the shift as next-state temporaries), and (c) cuts the IRAM to 256 rows
(section 5.4). Two bodies, otherwise identical: **landed** keeps
``bram = rd_reg; rd_reg = mem[a]``; **amended** reads ``bram = mem[a]`` and
counts the port's ``L = 1`` as the memory's.

**Measured** (3.33 ns, Verilator; ``logs/catapult/fd12{a,l}_3p33/``). A
Wire-linked composite has no token alignment: the sink pushes a token every
cycle from reset, so its token ``t`` is held against RTL row ``t - k``. At
``k = 4`` (two Wire hops + the kernels' start skew) every control output of
both bodies matches; ``k = 0..3, 5, 6`` differ on the control outputs too:

* **amended**: 24,971/25,002 defined slots; the 31 that differ are all
  ``bundle_data``, all in the first cycles after a reset of programs 1-3,
  and are exactly the slots where a *write-first* IRAM would differ from the
  RTL's old-word read (31/31 positions and 31/31 values, checked against
  ``ref_ctrl_front`` with the write applied before the read) -- a separate
  finding, D-6;
* **landed**: 22,992/25,002; 2,010 ``bundle_data`` slots in all four
  programs, each the word one fetch address behind: one register late.

**T-2 confirmed, and the amendment's rule is what Catapult's lowering
already does**: on Wire links the IRAM's ``L = 1`` read issued in owner
iteration ``t`` is the value of iteration ``t + 1`` (``t + L``); a body
written for the Stream links (``t + L - 1``) counts the register twice. The
amendment makes the Stream lowering the one to change (deliver at ``t + L``),
so the amended body is the one body for both link kinds; until then the
simulator/csim and Catapult need different bodies, and nothing reports it.
Caveat: the composite that confirms it is not the one tracks A built (D-13
refuses that), so the regression test per link kind the amendment asks for
needs D-3's form.

5. Hypotheses and probes
========================

5.1 H4 (I1 per cycle on Catapult RTL) and H12
---------------------------------------------

**Confirmed.** ``seq_issue:locked`` matches ``ref_ctrl_issue`` per cycle on
every Phase 0 program trace and image at both clocks (section 2); the issue
cycle of every bundle is the RTL's (+2). H12 (Q1(b) without an 85-bit port):
the three slot commands synthesise and run cycle for cycle (section 3).

5.2 H2 (S1 at ``latency=S_LAT``)
--------------------------------

**Confirmed in the row form, with a different pin.** S1 carries the
``S_LAT``-deep write pipe as data, so the Catapult pin is ``latency=1`` (U3
track C section 2: rows + 1) and a write is visible ``S_LAT`` rows later; all
three ``S_LAT`` builds match per cycle with one body. A ``latency=S_LAT`` pin
belongs to a combinational S1 that no track built. ``S_LAT`` as a D-20
booking has no manifest number to be checked against (D-7).

5.3 H3 (F1 + L1 match; IRAM / loop buffer inference)
----------------------------------------------------

**F1/L1 match per cycle** (fq at both clocks, loop at both clocks, iram with
a 256-row register IRAM). **Inference:** the 4,096 x 128 IRAM as a body array
is mapped to ``ccs_sample_mem.ccs_ram_sync_1R1W`` (MEM-4) and **refused at
II=1** (SCHD-30: the read of row ``t`` feeds the read register in the same
iteration as the write -- a synchronous RAM returns it a cycle later),
pinned or free; partitioned into registers at 256 rows it needs
``REGISTER_THRESHOLD 4096`` (MEM-8 otherwise) and matches; at 4,096 rows as
registers (the D-12 ``registers`` server) ``architect`` grew to 15.7 GB in
10 min and was stopped (5.4). The 24 x 128 loop buffer (``lbmem``,
kernel-local) became registers with no directive. So no Catapult form of a
4,096-row IRAM reaches II=1 with the libraries on this host (no macro, no
1R1W-with-bypass model): a cycle-locked IRAM needs an ``Sram`` macro with a
registered read (asic_memories) or the D-12 ``rw``-port refusal (H11).

5.4 The 4,096-row ``registers`` IRAM
------------------------------------

``fetch_d12`` at the RTL's 4,096 rows (``fd12_amended_3p33``) spent 583 s in
``architect`` and reached 15.7 GB (``SOL-15`` lines) before it was stopped
by hand (no result). At 256 rows the same composite builds in 77 s, 860 MB.
The 256-row cut is exact on these traces: every write is below word 48, a
read above the written words is uninitialised (masked), and both the queue
and the loader mask the address.

5.5 H7 again: D1 over Streams on Catapult RTL
---------------------------------------------

``dma:streams_reset`` (``src`` -> engine -> ``sink``, depth-2 channels, every
kernel II 1) computes every row (805,652/805,652) at **1.333 cycles per row**
(13,238 stall cycles in 39,718 rows) with outputs 5-6 cycles after their row:
the "depth-2 link between two II-1 kernels sustains 2 tokens per 3 cycles"
of ``minitpu_rtl_mxu`` on another unit. Every kernel's manifest says II 1;
the composite's rate is not a manifest number (``latency.composite``:
MISMATCH). The one-kernel D1 is cycle for cycle.

5.6 H11: the VMEM DMA port beside the compute port at II=1
----------------------------------------------------------

**Confirmed refused**, as ``asic_memories`` s.2.2 predicted: in
``dma_vmem:d12_reset_r256`` the generated ``vmem_mem`` server (two ``rw``
ports, 256 x 1,024 b) is mapped to ``ccs_ram_sync_1R1W_rwport`` and
``could not schedule partition '/dma_vmem_core_r256_packed/vmem_mem_0/run' -
could not schedule even with unlimited resources`` (SCHD-30: the read and
the write of one RAM in one II=1 iteration). Partitioning 262,144 bits into
registers was not attempted (5.4's blow-up at a quarter of that). AMC is
H11's other place to ask (track E).

5.7 H13 (W2, the interlock Option)
----------------------------------

**Not run**: no W2 variant landed in wave 1 (track B built W1 and the
self-timed probe; plan P-6 makes W2 a probe the owner decides, O3).

5.8 D-24 on Catapult: ``vpu_wb:selftimed``
------------------------------------------

The self-timed write port (three class units, a merge polling ``empty()``
then ``Pop()``) **synthesises** (57 s; every unit II 1) and **stalls on the
RTL**: after 547 command rows and 33 claims on each output, no port moves for
20,000 cycles (the driver's stall guard). The emitter lowers ``empty()`` to
the FIFO's ``empty`` signal read as an ``sc_in<bool>`` beside the Connections
``Pop`` (seen in ``kernel.cpp``); csim ran it (track B: UNIT-DIFF by design),
the simulator hangs (F-B4). [I] The Catapult schedule samples that signal
out of step with the handshake, so the merge stops popping; not isolated. So
the self-timed form has no Catapult RTL comparison (cycles) yet; area is in
section 6 (DC 4,137 um2 at 3.33 ns against locked W1's 4,696: the self-timed class units carry no destination-tag pipelines).

What the numbers say:

* **Combinational C1 units cost a boundary, not logic.** ``sequencer_decoder``,
  ``_agu_resolve``, ``_vpu_adapter`` and ``dma_addr_gen`` are 72-1,614 um2 of
  gates with no register in MiniTPU; the Catapult forms add an input and an
  output register on every bit plus the valid/ready logic (159-378 flops).
  The like-for-like Catapult form is plan C2 (``Wire[..., comb]`` units),
  which no track built.
* **Reset storage.** Catapult resets every register (D-13's recorded
  deviation): the fetch queue's 560 payload flops are unreset in MiniTPU (28
  reset) and reset here; the loop buffer's 3,072 likewise. Together with the
  I/O registers this is most of the area difference on ``fq`` and
  ``loop_ctrl``.
* **Unreset storage (D-14), one data point.** The 256-row IRAM as reset
  registers (``fetch:iram`` form, 33,829 reset flops) is 216,231 um2; as the
  D-12 server's unreset ``sc_signal`` array (``f1_d12`` amended, 34,303
  flops of which 1,535 reset) the whole composite is 191,510 um2 -- 11 %
  less, with the boundary units included. Not U3's H14 measurement (the
  units differ), but the direction it predicted.
* **The DMA** is 2.0x MiniTPU's (35,620 vs 17,645 um2 at 3.33 ns): the
  landing payload is reset here (``bits_reset``: C2 keeps ``reset=False``
  out of a Stream-port kernel; 5,082 reset flops vs MiniTPU's 2,839 of which
  623 reset), and the four row ports add about 2,100 I/O flops.
* **The sequencer as a whole** (issue + fq + loop + sagu, Allo, summed:
  48,216 um2 at 3.33 ns) against MiniTPU's ``sequencer`` with its IRAM cut to
  2 rows (28,783): the boundaries between the four units are Connections
  ports with registers here and wires in ``sequencer.sv``, and every Allo
  register is reset.
* **Timing.** Every one-kernel unit closes at 3.33 ns, and at 2.0 ns where
  Catapult built it; ``dma`` did not schedule at 2.0 ns, and the MiniTPU
  sequencer itself misses 2.0 ns in DC (worst slack -0.06 ns).

   * - id
     - class
     - finding
     - smallest change / proposal
   * - D-1
     - missing abstraction (emitter; U3 C1/C2 again)
     - Every U4 unit with a ``[n, k]`` lane array (P-8) or a port read under a
       condition reaches Catapult as RAM pins, so no per-cycle boundary: 9
       of the 13 landed units needed a track-D form (``forms/``). The forms

       declaration; and an emitter error (not RAM pins) on a conditional port
       read in a pinned kernel.
   * - D-2
     - workaround (schedule; U3 proposal 6 again)
     - ``s.unroll("k:name")`` reaches the first of several sibling loops that
       share a name (every ``for k`` is ``k``; ``get_affine_loop_nests``
       follows one path), so ``vpu_wb``'s 12 ``k`` loops stayed rolled,
       merged into the pipelined loop and made the manifest ``unreliable``
       (each vector up to 16 iterations). Worked around by setting
       ``unroll=0`` on every nested ``affine.for`` (``--unroll-nested``):

       frontend naming sibling loops uniquely.

     - missing abstraction (D-12 / D-13)
     - A D-12 memory's owner on the SystemC target is a comb-pin kernel, and
       D-13 refuses the composition tracks A and C built: a comb pin cannot
       read a Stream, and no state may be read after a store in the
       iteration. ``f1_d12`` needed Wire boundary links and a
       read-then-store rewrite of its body to build at all; then its outputs
       have no token alignment (a shift of 4 rows found by search).

       the owner has Stream ports, or the server taking its address from the
       owner over a Stream with the latency counted (D-12 amended); a

     - finding (Catapult, budget)

       ``architect`` past 15.7 GB in 10 min (stopped). The same at 256 rows:
       77 s.

       (naming ``sram`` / ``Sram``), as ``replica`` is refused off FPGA.
   * - D-5
     - semantic mismatch (Catapult memory inference; H3, H11)
     - A body array read and written in one II=1 iteration (the IRAM, the
