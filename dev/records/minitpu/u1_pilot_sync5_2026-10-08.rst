**Run 1's abort: an environment hazard of the full-suite env, not a branch
regression.** ``Fatal Python error: Aborted`` in
``tests/ip_integration/test_rtl.py::test_stream_backpressure_and_repeated_calls``
(inside ``allo/backend/simulator.py`` ``__init__``). It reproduces with just
``tests/utils/test_backend_utils.py tests/ip_integration`` under
``env-zhang21.sh``. Isolated: in that env, after ``test_backend_utils``
the process has the system ``/lib64/libstdc++.so.6`` loaded. The pybind modules
built by Catapult's g++ 10.3 then fail to import (``GLIBCXX_3.4.26 not found``,
the same five failures as on the baseline), and a later in-process RTL model
built with a newer g++ aborts the interpreter. Each file alone passes in that env,
and the whole directory under the plain env with ``VERILATOR`` set does not abort
(58 passed, 6 failed: the same pybind/``lib_gemm`` failures, now
``GLIBCXX_3.4.32``). The Verilator tests are covered by the dedicated 63/1 run
(s.2). Consequence for the next sync: run ``tests/ip_integration`` as its own
pytest invocation in the plain env with ``VERILATOR`` set, not inside the
``env-zhang21.sh`` full suite.

========

* Brief vs method: the brief said not to source ``env-zhang21.sh`` for
  python runs. The gates ran in the plain env, but ``systemc_csim``, eva,
  ``check`` and the full pytest need Catapult's ``MGC_HOME``/SystemC, so those

  what keeps Catapult's python from shadowing the env's. This is sync 4's form.
