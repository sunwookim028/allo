2. The forms, and why the landed ones needed a track-C shape
============================================================

Every landed form writes the RTL's registers as data (checkpoint 6: one kernel
iteration per RTL cycle, the register edges as rows). On Catapult that means
**the Pop->Push edge of a row is the row's own edge**: a row form with ``k``
rows of delay written as data and the kernel's I/O latency pinned to 1
(``latency=1``, ``cycle set {Push} -from {Pop} -equal 1``) is MiniTPU's
``k + 1``. The staged SFU's 4 rows + 1 = ``VPU_SFU_LATENCY`` 5; the PE's rows
+ 1 = its contract; the tree's ``2 LEVELS`` rows + 1 = 13/9. So P-3's "pin SFU 5,
tree 13/9, PE 4" is one of two pins: ``latency=5`` on the *combinational* S1
(Catapult places the five registers), or ``latency=1`` on a row form (the
registers are already in the data). Both were run on the SFU and both are
cycle-equal (section 1).

The landed forms needed three changes to reach Connections RTL at all, each a
finding on the emitter's port rules, none on the units' logic:

* **C1 -- a 2-D lane array is not a stream.** ``isSeqStreamable``
  (``EmitSystemC.cpp:945``) streams only a rank-1 boundary array with one
  access site directly under one loop; ``uint16[n, N]`` (P-8's lane arrays:
  the tree's ``data_i``/``lane_result_o``, the transpose's words, the array's
  and the MXU's ``[N * D]`` lane memories) becomes **RAM pins**
  (``_radr/_re/_q/_rrdy``, ``_wadr/_d/_we/_wrdy`` -- a memory the integrator
  provides, read one word per cycle). That is a different unit boundary from
  MiniTPU's (a 1,024-bit port per cycle), and no per-cycle RTL comparison in
  the harness's shapes. Track-C forms ``forms/tree_wide.py``,
  ``forms/tree_wide_staged.py``, ``forms/transpose_wide.py`` pack the lanes
  into one ``UInt(16 N)`` word per row (``allo.meta_for`` slices; the emitter
  gives ``ap_uint<1024>`` Connections ports): the RTL's own port shape, and
  numpy-free (the simulator cannot run them, B6; Catapult needs no run).
* **C2 -- a conditional port access is not a stream.** The landed S2
  (``sfu.staged``) warms up and drains (``if t < n: read``, ``if t >= 4:
  write`` over ``n + 4`` iterations), and ``xlu_transpose.trace`` stores
  ``rvo[t]`` under ``if r == 0 ... else``. Each makes the array RAM pins, so
  ``latency=`` is refused -- verbatim: ``ValueError: latency=1 on sfu_k_0: it
  has no Connections In/Out pair (Wire ports?). Catapult cannot pin a Wire
  port's latency ...`` -- the refusal is right (D-1), the message names the
  wrong cause. ``forms/sfu_staged_rows.py`` pops and pushes once per row over
  exactly ``n`` rows (output row ``t`` is input row ``t - 4``; the comparator
  shifts, ``--shift 4``); ``transpose_wide`` stores ``rvo[t] = 0 if r == 0
  else v`` once.
* **C5 -- a ``Stateful`` array is a RAM unless partitioned.** The transpose's
  ``tile: uint16[16, 16] @ Stateful`` was mapped to
  ``ccs_sample_mem.ccs_ram_sync_1R1W`` (a synchronous RAM, one read port,
  read visible the next cycle), so ``latency=1`` was refused: ``chained data
  dependency ... from operation MEMORYREAD "l_S_t_0_t:v557:read_mem(
  __stateful_tx_0_tile_1:rsc.@)" ... mapped to "ccs_sample_mem.
  ccs_ram_sync_1R1W_rwport(14,16,8,256,256,16,5)"`` (SCHD-6/SCHD-30), and a
  64-way crossing read would be 64 cycles. MiniTPU's tile is 256 flops with a
  mux. ``s.partition("tx_0:tile")`` (complete) emits ``#pragma hls_resource
  ... map_to_module="[Register]"`` on the Stateful (the U2 ``vpu_regfile``
  precedent), which is the honest form; it is a *schedule* on the unit that
  nothing in the source declares -- D-12's ``Memory(ports=)`` would (a
  16-port read is a register array), and is not in this tree (track A, X2).

Loops: every constant-trip inner loop is unrolled (``--unroll-inner``: the
shift pipes, the node loops, ``leading_zeros17/19``'s ``offset``), and each
kernel's iteration loop is pipelined at II = 1 -- a rolled inner loop merged
into the pipelined loop is the one way the manifest lies
(``latency_report_2026-10-02.rst``). ``mxu_pe.bits``'s nested ``def
leading_zeros19`` is emitted as one helper function with one ``offset`` loop,
so one ``unroll`` covers it (H4 below).

3. Hypotheses
=============

* **H2 (2,048-entry constant ROMs; does Catapult infer a ROM?)** -- **yes.**
  ``sfu.bits``'s four kernel-local constant arrays (``rom_gelu``, ``rom_exp``
  2,048 x int32; ``recip_pwl``, ``rsqrt_pwl`` 32 x int32, emitted as
  ``static const int32_t`` inside the thread, finding A1's form) become four
  Catapult ROM components in ``rtl.rpt``: ``ROM_1i11_1o12`` (score 1908.8),
  ``ROM_1i11_1o16`` (1493.9), two ``ROM_1i5_1o21`` (120.8, 118.4) -- an
  11-bit address and a 12- or 16-bit word: Catapult trimmed the constant top
  bits of the exp table to 12 output bits, and of every table from int32 to
  the bits that vary. They are combinational ROM blocks of the
  ``nangate-45nm_beh`` library (``rtl.rpt`` ``ROM: 0.0`` in the memory row:
  no memory macro), as MiniTPU's ``(* rom_style = "block" *)`` arrays become
  in DC. No abstraction was needed beyond the constant array; the H2 question
  for RTLGen and AMC stays with track D.
* **H3 (T1 matches; Catapult's free depth != 13 unless pinned)** -- **the
  free depth is the *I/O* depth, and the register depth is in the data.**
  ``tree_wide`` (T1's body) free at 3.33 ns: II 1, manifest latency 1,
  values 204,120/204,120 per row, but the tap output was pushed in the Pop's
  own c-step (``lane_result_o`` L = 0, the other three 1): its Push depends
  on no Pop of the iteration, so the scheduler is free to put it anywhere,
  and the manifest's one number (the max over pairs) hides it. Pinned
  ``latency=1`` makes every (Push, Pop) pair 1 -> **cycle-equal** (section
  1). So the pin is still needed at U3, for a reason D-10 did not list: not
  to reach the depth (the rows carry it) but to hold *every* output to one
  edge. ``rtl.rpt`` slack is -1.46 ns on both; DC decides (section 5).
* **H4 (the 63 composed adders each need ``leading_zeros17`` unrolled: C10
  for ``@df.unit``, not for ``compose.unit``)** -- in every form here
  ``add_bits``/``leading_zeros17`` (and the PE's nested ``leading_zeros19``)
  are emitted as **one helper function** per module, called from every node
  or unit body, so ``s.unroll("leading_zeros17:offset")`` is one directive
  for 15 or 63 nodes: C10 does not recur on the SystemC path for ``@df.kernel``
  (T1 body) nor for ``compose.unit`` (T2, P2, A1: the PE's ``offset`` loop is
  one per unit *instance* because B inlined it into the body, and
  ``--unroll-inner`` lists them). T2 (``xlu_tree_compose``, n16) through Catapult: ``add_bits`` and ``leading_zeros17`` are defined **once** in the emitted ``kernel.cpp`` (2 definitions for 15 node kernels), the one ``unroll("leading_zeros17:offset")`` reaches every node, and all 15 ``add_low``/``add_tap``/``add_high`` kernels schedule at latency 2, II 1. **H4: C10 does not recur on this path for either unit mechanism.** What T2 does cost is the composition's boundary: ``tree_feed`` reads the 16 lanes from a RAM-pin array and puts 16 tokens per row (II 33), the sink II 3 -- the lane-array boundary of C1, not the adders.
* **H7 (a Stream-linked array computes the contract but not the cycle
  model; push->valid > 82)** -- **measured on Catapult RTL for the first
  time, and it is a rate as much as a latency.** ``mxu_pe.unit`` (P2: one PE
  between a driver and a sink over depth-2 Connections FIFOs): every defined
  slot matches per row (360,196/360,196) but the composite runs **2.0 cycles
  per row** and every output lags its input row by 5 or 7 cycles
  (alternating), where ``mxu_pe.bits`` runs 1 cycle per row at L = 1.
  ``mxu_systolic_array.streams`` at DIM 2 (A1): 79,983/79,983 per row, **9.0
  cycles per row** (the driver reads D words of each ``[N * D]`` RAM-pin
  array per row: II 9), outputs 12-13 cycles after the row. The cycle model
  holds *in token time* (B's P-11) and fails *in cycles* exactly as the plan
  expected, with the numbers: 2x the rows for one PE hop, 9x for a lane
  memory read per row; the Catapult FIFO hop costs what ``u3_fifo_composed``
  measured. ``mxu.lockstep`` at DIM 4 (M1, every PE pipelined, front and back not): **111,067/111,067 defined slots per row** -- the push/commit/pop contract holds on Catapult RTL -- at **74.06 cycles per row** (``mxu_front`` II 59 with one rolled loop merged, manifest ``unreliable`` as D-10 requires; ``mxu_back`` II 26), so the contract's ``2 + 5 DIM = 22`` rows are **1,631 cycles** of push->valid (identity program: 22 rows x 74.06; the random programs' 1-row distance is 77 cycles): the manifest number the owner asked for, and the measure of what a lane-memory boundary and two FIFO hops cost when every row is a token. At DIM 4 the array alone (A1) is 79,849/79,849 per row at 17.0 cycles per row, outputs 20-25 cycles after their row.
* **H8 / A2 (Wire-locked grid)** -- not attempted (plan: expected blocked).
* **H14 (D-14 unreset payload: DC area within 5 % of MiniTPU; reset form
  +10-20 %)** -- **not reached as stated**: the one unreset form in the
  track-A units (``xlu_transpose.trace_unreset``) is refused by the emitter
  on a kernel with non-Wire ports (A6, reproduced verbatim here:
  ``error: unreset storage `tile` (tx_0): the kernel has a non-Wire argument
  (argument 0); the write runs at every clock edge, which matches the
  kernel's iterations only when every port is a Wire``), and the forms'
  payload registers (the SFU stages, the tree pipes, the PE's registers) are
  kernel-local scalars, which Catapult resets as part of the thread state.
  What was measured instead: the **reset-flop share** of the Catapult RTLs'
  sequential area against MiniTPU's (section 5).

4. Findings
===========

Classified per D-9. Verbatim messages are in ``logs/``.

**C1 -- missing abstraction (emitter): a lane array is not a port.** A
rank-2 boundary array (P-8's ``uint16[n, N]``) is never a Connections
stream (``isSeqStreamable`` is rank-1 only) and becomes RAM pins, one word
per cycle: the landed tree, transpose, array and MXU forms have no
one-word-per-cycle RTL boundary, so none can be held to MiniTPU per cycle as
written, and a pipelined kernel that reads D words of one such array per
iteration **cannot be II = 1 at all** (``array_sink_0``/``mxu_back_0``:
``could not schedule partition ... even with unlimited resources``,
SCHD-30). The track-C forms pack the lanes into one ``UInt(16 N)`` word
(the RTL's own port) -- a *workaround* for the units, and a gap for the
model: a lane array that is one word per iteration should be one port.
Proposal: a rank-2 array whose first index is the iteration variable and
whose inner dimension is fully read/written per iteration streams as one
``ac_int<W * N>`` (or N ports), by declaration (``Stream[UInt(16)[N]]``
style) rather than by inference.

**C2 -- workaround (emitter rule, correct): a conditional port access is not
a stream.** The landed ``sfu.staged`` warm-up/drain (``if t < n``, ``if t >=
4`` over ``n + 4`` iterations) and the transpose's ``if r == 0: rvo[t] = 0
else rvo[t] = v`` make the array RAM pins; ``latency=`` is then refused with
a message about *Wire* ports (``it has no Connections In/Out pair (Wire
ports?)``), which is the wrong cause. The refusal is right (a skipped Pop
would desynchronise the stream, the emitter's comment). The row forms
(``sfu_staged_rows``: one Pop and one Push per row over ``n`` rows, output
row ``t`` = input row ``t - 4``; ``rvo[t] = 0 if r == 0 else v``) are the
honest shape; a pipe-as-data kernel has no warm-up on a stream. Proposal: the
refusal names the arrays that fell to RAM pins and why (conditional access /
rank / multiple sites).

**C3 -- semantic gap (D-10 manifest): a row form's latency is rows + I/O.**
``latency.json`` reports the Pop->Push distance (1 for every row form); the
unit's latency is that plus the rows written as data (4 for the SFU, 8/4
for the n16 tree, the PE's). ``harness/latency.verdict`` therefore prints
``LATENCY-MISMATCH ... reported 1, measured 5`` on a bit-exact,
cycle-equal build unless the comparator separates the two (``u3c_cmp.py
--shift``: ``5 rows as data + I/O {1}``). The manifest cannot know the
rows; the form can. Proposal: a kernel written as rows declares them
(``rows=4``, or the ``latency=`` of a row form means rows + 1), and the
manifest carries both, so an assembler's table (D-10) reads the unit's
number.

**C4 -- finding (scheduler): the pin holds every output to one edge; the
free schedule does not.** ``tree_wide`` free: ``lane_result_o`` pushed at
L = 0 (same c-step as the Pops: its Push depends on no Pop), the other
outputs at 1 -- one output a cycle early relative to MiniTPU, values intact
per row, the manifest showing 1. Pinned 1: all four at 1. On ``pe_unit_1_1``
in the array, the manifest itself says ``latency=0``. A unit whose outputs
are registered state (every row form) has no data dependence from Pop to
Push, so without the pin Catapult places each Push where it likes.
Relevant to D-10's "``latency=`` only where a contract demands": a
multi-output row form demands it for alignment, not depth.

**C5 -- workaround (two Catapult directives the source does not say): a
``Stateful`` array is a RAM.** ``tile @ Stateful`` (16 x 16) was mapped to
``ccs_sample_mem.ccs_ram_sync_1R1W`` (one read port, next-cycle data), so a
64-way crossing read per row is impossible and ``latency=1`` was refused
(SCHD-6 ``MEMORYREAD ... mapped to ccs_ram_sync_1R1W_rwport(14,16,8,256,
256,16,5)``). ``s.partition("tx_0:tile")`` emits ``hls_resource ...
[Register]`` (the U2 ``vpu_regfile`` precedent) -- and then Catapult refused
to split it: ``Error: Splitting of Resource '/top/tx_0/__stateful_tx_0_tile_1
_rsc' into 256 variables could cause excessive runtime or memory
requirements (MEM-8) / Please select a library with memories or increase
REGISTER_THRESHOLD``. ``directive set -REGISTER_THRESHOLD 4096`` (hand-set
in ``run.tcl`` via ``--tcl``, recorded) builds it: 256 registers, L = 1 at
both clocks, cycle-equal. Neither the partition nor the threshold is in the
Allo source; D-12's ``Memory(ports=...)`` is where a 16-way read would be
declared (track A, X2: not in this tree). Proposal: the SystemC backend sets
``REGISTER_THRESHOLD`` to the size of the largest fully partitioned
``Stateful`` it emits, and refuses a crossing read on an unpartitioned one.

**C6 -- semantic mismatch (tool timing): Catapult's rtl.rpt slack vs DC
(N4 again, larger).** The n16 ``tree_wide`` (a 4-level bf16 tree in one
c-step, II 1) and ``mxu_pe.bits`` schedule at 3.33 ns with ``rtl.rpt``
slack -1.46 / -0.31 ns; DC's numbers for the same RTL are in section 5.
Catapult's library model of a bf16 adder chain and DC's FreePDK45 disagree
by more than a cycle at 2.0 ns on the PE (-1.89). The staged tree with one
adder per c-step was *refused* at ``latency=1`` at 3.33 ns (SCHD-30, the
``add_bits ... or`` chain) while the full-tree form was *accepted* at the
same pin: the chain the pin constrains is Pop->Push, and in the full-tree
form nothing on that path is an adder -- the adders sit on the
register-to-register path, which the scheduler checks against the clock
with its own (optimistic) model. The measured truth is DC's.

**C7 -- bug (my form, caught by the oracle, twice): the staged tree's
register order.** The first ``tree_wide_staged`` updated ``stB <= stA`` before
computing ``stA <= f(stB)``, so each level cost one row, not two, and read
the valid pipe before the cycle's clear: 125,907/204,120 on RTL. The second
computed from the old registers but read the outputs after the update and
the valid pipe after a shift one entry short: 76,999/204,120, every
difference one row early. The third (payload read before the update, valid
pipes one entry deeper read after shift and clear, as T1 and ``sfu.staged``
do) matches 204,120/204,120. Recorded because it is the second time (track
B's finding 7) that a hand-written pipe-as-data form was wrong only in its
*ordering*, and only the per-cycle RTL oracle said so -- an argument for the
pipe-as-data form being generated from a declaration (stage count per
level) rather than written by hand.

**C8 -- finding (Catapult, scale):** the unrolled n16 tree takes Catapult
19-22 min per run (``dpfsm`` 500-1,100 s on 15 unrolled adders), the SFU
and PE ~2 min, the DIM-2 array 4 min; the n64 tree and the DIM-4 array/MXU
were not finished in this session's budget (section 8).


**C9 -- bug candidate (SystemC emitter / Catapult RTL): a Stream polled with
``empty()`` and fed by ``try_put`` is not a FIFO on RTL.** Track B's finding 3
measured, as asked: the MXU with its lane FIFOs as ``Stream[UInt(64), 16]``
(``gather_try`` ``try_put``\ s a finished group, ``pop_engine`` polls every
lane's ``empty()`` and ``get``\ s on a pop; B's probe units unchanged,
``forms/mxu_streams_fifo.py``), DIM 2, 3.33 ns, every Phase 0 program, on
Catapult RTL through the memory-pin comparator. Catapult schedules it (PEs
1 / 1, ``gather_try`` 3 / 4, ``pop_engine`` 1 / **10**, ``mxu_front`` 1 / 5
unreliable; 10.0 cycles per row). **The contract fails**: pops in order equal
**0/2423, 0/2420, 0/2424** on the random programs and 0/16 on
``fifo-full-exact`` (``waiting-pops`` alone 4/4); ``output_valid_o`` is high
from cycle 0 on nine programs (``first valid catapult 0`` where the RTL's is
19-25) and ``overflow`` delivers 17 pops for the RTL's 16 -- the lanes' heads
are consumed out of step. In csim B saw the *data* intact in order and only
the *cycle* gone (943/943 in order on ``random-0``); on RTL the order is gone
too. The likely mechanism is the ``empty()`` sideband: ``laneq[lane]_empty``
is an ``sc_in<bool>`` driven by the top-level ``AlloFifo``'s ``empty_o``, and
a value of 0 before the first token (or one cycle stale after a ``get``) makes
the engine ``get()`` from an empty lane -- ``u3_fifo_composed`` cosim'd one
FIFO, not a polled gather/pop pair. By contrast M1's explicit ring
(``mxu.lockstep``) holds the contract on RTL on every program (above).
Proposal: a Verilator regression of one ``try_put``/``empty()``/``get`` lane
on Catapult RTL (the form is in ``forms/mxu_streams_fifo.py``), and the
``empty_o`` reset value checked in ``AlloFifo``/``AlloFifoC``. Until then P-12
(explicit rings for the verdict) stands on RTL as well as on the simulator.

Reading it:

* **The SFU is the one unit where Catapult's RTL is smaller** (0.74x at
  3.33 ns): Catapult trimmed the ROMs to the bits that vary (12-bit exp
  words, H2) and S1 at ``latency=5`` keeps 153 flops against MiniTPU's 269
  (the five stages' payload is not all needed once the scheduler chooses
  where the registers go). The row form (every register as written) is
  1.09-1.13x: the handshake and the full register set.
* **The PE is 1.66-1.77x**, the tree 1.59-1.63x, the transpose 1.48x (6,230
  flops vs 5,125: the 1,024-bit Connections data register plus the
  handshake on both words). U1's acc24 was 1.72x on the same arithmetic
  transcription (N7), so the PE's ratio is the acc24 adder's, not new.
* **A composed form costs 2.2-3.6x**: the depth-2 FIFO per link, a driver
  and a sink kernel each with their own FSM, and the PE's three 32/64-bit
  token registers. On the DIM-2 array the 4 PEs' logic is a minority of the
  18,060 um2.
* **Reset-flop share (H14's measurable part):** every Catapult register is
  reset (``RESET_CLEARS_ALL_REGS`` default; no ``Stateful(reset=False)`` in
  these forms), while MiniTPU resets only valids, ops and commits: the
  transpose's 4,096 tile flops, the tree's leaf and level payload, the PE's
  payload are unreset there. The flop *count* gap above (sfu rows +32 to +43,
  tree +1,193 to +1,338, transpose +1,105, PE +163 to +195) is the handshake
  registers and Catapult's FSM state, not reset; the reset *cell* penalty
  itself (a reset flop vs a plain flop in FreePDK45) is the 5 % U2 measured
  on the register file, and was not isolated here.

6. Proposals for the core (no patches here)
===========================================

1. ``EmitSystemC.cpp`` ``isSeqStreamable`` / the port rule (C1): a rank-2
   boundary array indexed ``[iteration, lane]`` with every lane accessed once
   per iteration streams as one word (or N ports) -- preferably by a
   declaration on the region argument, so the simulator and csim keep the
   lane array and the RTL gets the word. Until then the track-C ``*_wide``
   forms are the Catapult shape of every lane-array unit.
2. The ``latency=`` refusal message (C2): name the arrays that fell to RAM
   pins and the reason (conditional access, rank, several sites), not
   "Wire ports?".
3. ``latency.json`` for a row form (C3): carry the rows written as data
   beside the I/O latency (``rows``), or define ``latency=L`` on a row form
   as rows + I/O so the manifest's number is the unit's; ``harness/latency.
   verdict`` then needs no ``--shift``. D-10 follow-up, for the owner.
4. D-10 text (C4): "``latency=`` only where a contract demands" should
   include *a multi-output row form*, whose outputs the free schedule places
   on different edges (one a cycle early) while the manifest reports one
   number; or the manifest reports per-port I/O latency.
5. ``allo/backend/hls.py`` SystemC tcl (C5): set ``REGISTER_THRESHOLD`` to the
   largest fully partitioned ``Stateful`` the emission contains; refuse a
   per-row crossing read of an unpartitioned ``Stateful`` (it is a one-port
   RAM in Catapult) naming the storage. D-12's ``Memory(ports=)`` is the
   declaration this stands in for.
6. ``u3c_build.py``'s "ambiguous loop name" (two bands of one kernel with the
   same induction variable, ``tree_sink``'s two ``k`` loops): ``s.unroll``
   raises ``Find multiple bands containing loop k``; a loop handle by band
   (``kernel:band.loop``) would make every emitted loop addressable.

7. Provisional calls made (D-9)
===============================

* **P-C1. Cycle-equal is judged with ``latency=1`` on a row form.** The
  landed forms carry the RTL's registers as rows; the Pop->Push edge is the
  row's edge, so the pin that makes the Allo RTL show MiniTPU's value on
  MiniTPU's edge is 1, not the declared count. P-3's numbers (SFU 5, tree
  13/9, PE 4) were pinned on S1 as 5 (the combinational SFU, Catapult placing
  the registers) and *reached* on every row form as rows + 1. *Reason:*
  section 2; both SFU pins are cycle-equal and bit-exact.
* **P-C2. The wide-word forms are the Catapult shape of the lane-array
  units**, kept in the record's ``forms/`` (as U1 kept its ``wire/`` forms),
  not in ``units/*.py``'s ``VARIANTS`` (the simulator cannot run a 1,024-bit
  numpy port, B6). *Reason:* C1; the body is the landed body.
* **P-C3. Composites are judged per row on the RTL and their cycles
  reported, not pinned** (P-2/P-3): P2 and A1 ``UNIT-MATCH`` per row with
  the rate and skew beside them. *Reason:* a self-timed form has no edge to
  pin; the numbers are the H7 evidence the owner asked for.
* **P-C4. Two Catapult directives set by hand are recorded as such** (the
  ``Stateful`` partition and ``REGISTER_THRESHOLD``, C5); every other build
  is Allo's ``run.tcl`` as emitted, with ``latency=`` as a build config.
* **P-C5. MiniTPU's ``sfu.sv`` is synthesized in DC from a stand-in** whose
  two ``$readmemh`` ROMs are ``localparam`` arrays (``gen_sfu_dc.py``; every
  other line byte-identical, diffed). *Reason:* DC ignores ``initial`` and
  would synthesize empty ROMs; the ``.mem`` contents are the ROMs.
