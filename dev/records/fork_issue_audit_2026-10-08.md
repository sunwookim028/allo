### #9 -- Support of combinational wires in dataflow region

> **Decided by README D-13 and implemented on `main` for the SystemC/Catapult path.** `Wire[T]` exists in `allo/ir/types.py` (`:410`; the 2026-09-19 note that `types.py` has no `Wire` is stale), and a same-cycle output is declared as `Wire[T, comb]` / `Wire(..., comb=True)` (`:399-407`). The SystemC emitter builds one `SC_METHOD(comb)` per kernel over `sc_signal` storage (merge `a0c3c51a`, branch `backend-comb-wire`; `docs/source/backends/systemc.rst` "Combinational outputs"), which is the comb mode scoped in `c7402f9f`. Measured: a register file with three such read ports is bit-exact against MiniTPU's `vpu_regfile.sv` at read latency 0, write visible after 1, with no hand patch, and Catapult builds a clockless block (`dev/records/minitpu/u2_comb_read_2026-10-02.rst`, `u2_comb_wire_impl_2026-10-02.rst`). RTLGen and AMC refuse a `comb` port naming it (D-13). What remains -- a plain (non-comb) `Wire` in **csim** is offset by a few cycles, not wrong (`u2_comb_wire_impl` G3) -- is the correctness defect #25 tracks. Closing the feature request.

### #27 -- Allo, not Vitis, forbids a region-scope Stateful shared by two kernels

> **Decided by README D-11 and D-12; implemented on `main`.** D-11 (`5cd70c84`, merged `9d48a90f`): one `Stateful` has one kernel, and the refusal now happens in `_build_top` for **every** backend (`allo.dataflow.check_stateful_sharing`) -- before this the simulator ran four sharing kernels unordered and silently wrong (8,502/180,780, finding M2 in `dev/records/limitations/stateful_semantics_2026-10-02.rst`), so the asymmetry this issue measured ("Allo's rule, not Vitis's") was really "the emitters refused, the simulator did not". A region can state the ordered-sharing premise per Stateful (`@df.region(shared_stateful={"vregs": "..."})`), which the simulator honours and the HLS backends still refuse. D-12 (`4c6b37eb`): "a memory with several ports" is the thing the issue wanted -- `compose.Memory(rows=, ports=(Port(name, kind, latency, visible, count),), collision=)`, one owner **per port**; prototype `45b79d04` / `dev/records/minitpu/u2_d12_prototype_2026-10-04.rst`: a four-unit register file bit- and cycle-exact to `vpu_regfile.sv` on Catapult RTL (180,780/180,780) under both the `server` and `replica` lowerings, so the SystemC "bind one writer and one reader to one instance's two pin sets" fix sized here (~50-100 lines) is superseded. Tests: `tests/dataflow/test_stateful_semantics.py`, `tests/dataflow/test_compose_memory_ports.py`. Not changed, and carried by #11: Vitis refuses any memory with more than one owner (D-12 bullet), and `#pragma HLS stream type=unsync` is still never emitted (`EmitVivadoHLS.cpp:3422` records the measured 200-1014 limits). Closing as decided.

### #44 -- Coordination: ip-gap's reduction-tree unit as an allo.actions Machine

> **Done on `main` (`6ac1cf29`, 2026-09-24, "ip(actions): the tree as Actions -- a qualified yes, and the two things the model cannot say").** The five facts were taken from the real unit rather than a sketch: `tests/ip/test_reduce_actions.py::test_the_tree_is_expressible_as_actions_on_the_real_unit` builds the Machine from `examples/tinytpu/ip/reduce.py` as it composes, and every structural claim survives (which units the opcode reaches, the leaf order, the two output depths, the reassociation obligation). The two things the model cannot say are recorded in the same file: a unit's work count (`Machine.work` charged declared latency as occupancy, 5x off) and latency vs rate as two numbers. Since then README D-15 declares an engine's accumulate `order` (`sequential` | `tree`) as part of the function's identity (systolic vs tree differ on 74/8,192 bf16 outputs at DIM 16, 0 at int8) and D-20 makes the tree's derived numbers (13/9, 9/5) legality conditions checked at composition. Closing; the remaining arithmetic gap is #47.
