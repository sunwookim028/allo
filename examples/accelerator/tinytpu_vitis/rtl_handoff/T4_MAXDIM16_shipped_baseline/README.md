# TinyTPU-isa, T=4, MAXDIM=16 -- the published baseline

Vitis HLS 2023.2 generated Verilog for the ASIC synthesis-only
handoff (DC, freepdk-45nm, memories as flip-flops, no P&R).
Enter the flow at `sv2v` with `sv2v_manifest.f`; the top module
is `tinytpu_isa`.

## Configuration

- `T` = 4
- `MAXDIM` = 16
- `SPAD_ROWS` = 64
- `NVR` = 64
- `NAR` = 128
- `IMEM_SIZE` = 56
- `DMA_WORDS` = 1
- `data type` = int8 x int8 -> int32, mvout clips to int8

Emitted from allo commit `353ce3038e1a55b7b2301f6aed0c368ab8346571`.

## Measured on this configuration

Cycles are Vitis `cosim` (xsim), `ap_start` to `ap_done`,
`-m_axi_latency 0` unless stated, bit-exact against numpy.

- 4x4x4: **172** cycles
- 8x8x8: **262** cycles
- 12x12x12: **418** cycles
- 16x16x8: **484** cycles
- 16x16x16: **686** cycles

Vitis `csynth` on `xcu280-fsvh2892-2L-e`, 3.33 ns target:

- FF: 17075
- LUT: 26558
- BRAM: 40
- DSP: 14
- estimated clock: 2.431 ns (411.4 MHz)

## Notes

- This is the configuration the published 172/262/418/484/686 come from.
- The shipped DEFAULT is now MAXDIM=64 (docs/source/designs/benchmarks.rst); this build is kept as the baseline because every historical number is against it.
- Its scratchpad and vreg files are 64 rows each, DERIVED as MAXDIM^2/T. The design as published carried literal 512 and 256, which is more memory than MAXDIM=16 can address, so this build is strictly smaller than the one the cycle numbers were taken on while running the same programs.

`sv2v_manifest.f` and `MANIFEST.json` are generated by
`examples/accelerator/tinytpu_vitis/export_rtl.py`.
